Literal line semantics, not a programming-language parser:
- Only leading horizontal ASCII spaces/tabs may precede prefix.
- Prefix/suffix are exact literals. Optional suffix must end the line except
  trailing horizontal spaces/tabs. First declared matching rule wins; examples
  order more-specific prefixes before broader ones.
- Label is between markers, trimmed only at horizontal boundaries. Empty
  labels skipped. Offset is source line syntax start in UTF16 (document exact
  definition). ID binds buffer identity/original range/version AND ruleset so
  plugin refresh cannot reinterpret a captured target.
- No inferred multiline comment/string state. The existing per-line lexer
  cannot safely supply that guarantee. State prominently that literal rules
  can match text inside multiline code/string/comment constructs. Avoid regex,
  whole-language parsing or silently skipping unrelated source lines.
- AnchorID empty. Only source editor reveal; no rich preview/export controls.
