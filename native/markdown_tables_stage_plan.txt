Decisions already made:
- Header + delimiter with zero body rows is valid. Do not impose the old
  Milkdown header-plus-body minimum on our independently implemented format.
- Explicit finite rectangular pipe-table subset. Column alignment is display
  metadata from the delimiter line. Unsupported/ambiguous shapes preserve
  complete raw text with a bounded reason; never invent/discard cells.
- Source bytes/ranges remain authoritative. Preserve BOM/CRLF, outer pipes,
  whitespace padding, escapes, unknown neighboring constructs and untouched
  bytes. No automatic pretty-print or canonical table rewrite.
- Unescaped pipe remains structural even inside a code span. Define one-pass
  backslash-parity splitting explicitly; do not assume inline code makes pipe
  safe, and do not promise full GFM without tests for the declared grammar.
- A first rendering may show cell Markdown source literally, with clear
  wording. Do not apply inconsistent escape decoding or expose cell links with
  no source-identity navigation. Decide exact display semantics before code.
- Bound parser row/column/cell descriptors and per-frame widgets. Prefer
  flattening visible table rows under the existing virtual list, with a small
  explicit column cap. Do not build a whole giant table as a single List row.
- Narrow windows need an actual tested horizontal/wrapping strategy. Avoid
  arbitrary global scroll coupling or oversized toolbars. Use current palette.
- No per-cell editor instances: only the one active independent draft. Failed
  Flush retains draft/recovery and blocks save/switch/close. Newline/unescaped
  pipe input must never silently change table shape or rewrite adjacent cells.
- No parser engine/vendor/app host changes without demonstrated need.
