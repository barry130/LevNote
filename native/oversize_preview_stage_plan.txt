Design outcome:
1. Reuse exported parser budget constants/defaults, with one source of truth;
   do not make copies of magic numbers that can silently drift.
2. Before whole-buffer materialization for preview or export, inspect LenBytes
   and reject above its parser budget. Keep full editable buffer authoritative.
   Show a visible concise message and an available source route.
3. Cache the refusal by buffer pointer+version. Clear old parsed/layout caches
   and descriptors; do not retain obsolete source or a stale drawable view.
   Never clear a pending independent draft because of the size change.
4. Existing Flush order and conflict checks still apply. Oversize/source
   mutation while a draft exists must retain/recover that draft; export failure
   must not publish a partial/empty target.
   Markdown range-only Flush remains allowed above8MiB when mapped field guards
   succeed; do not turn a preview budget into a source editing restriction.
   Graph Flush needs a full parse, so it refuses before String and keeps draft.
5. Once content is back within budget or a new buffer replaces it, render again
   normally. Never permanently poison a view after one oversize document.
6. Audit secondary parse paths only as needed to prevent bypassing the guard;
   don't rewrite working formats or add arbitrary tighter normal limits.

Acceptance:
- Just over each parser default bound refuses before a proportional String/
  []byte allocation; measure allocation with the fixture constructed outside
  the measurement, and separate retained memory from cumulative allocation.
- Last-valid preview replaced by oversize source doesn't remain visible or
  exported; source bytes, buffer identity, selection, draft and undo survive.
- Repeated unchanged refusal is bounded, shrinking/reload recovers, readonly
  source navigation works. Add actual source/preview switch app coverage only
  where it exercises a meaningful lifecycle path beyond unit assertions.
- Focused checks first, then one integrated build after review if product code
  changes. Update real capability/resource wording and validation evidence.
