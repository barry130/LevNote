Scope and observable behavior:
1. Recognize a task marker only at the start of a body already recognized by
   the current simple list parser, in unordered AND ordered list items.
   Valid markers are [ ], [x], [X], followed by ASCII space/tab or end of item.
   Empty task labels are valid. Do not broaden nesting/indentation/CommonMark
   support in this stage. Invalid markers, escaped brackets, fenced/quoted text,
   inline-code strings, and [x]word remain ordinary text.
2. Publish an additive pure-format metadata contract before UI implementation.
   Preferred ListItem.Task *TaskMarker, TaskMarker{Range SourceRange, Checked
   bool}; Range covers the exact three ASCII marker bytes in original source.
   A task item's Text/TextRange/Inline describe its label after the marker and
   following ASCII whitespace. Non-task ListItems retain current semantics.
   Whole item/block Range and Document.Raw preserve all original bytes.
   A zero-length label range must be a valid position within the item.
3. Use MyGo's native checkbox primitive in each virtual list row. Checked state
   derives from the source model; a transient widget bool is not authority.
   Give keyboard/accessibility labels using bounded task text, visibly disable
   readonly controls, keep row identity stable. No animations/new dependencies.
4. Checkbox activation first completes pending composition/draft through Flush.
   Capture Buffer identity/version + exact item/marker identity beforehand;
   after Flush revalidate host identity, readonly, transaction ownership and map
   the enclosing item range through the edit journal. Target changes/deletion,
   Restore, expired history or failed Flush must visibly refuse and retain the
   draft/source/caret. Never resolve by list index, task label or old byte offset.
   Unrelated changes above may safely map; identical duplicate labels must not
   redirect an activation. Mapping alone does not prove the item is still a
   task: a newly inserted fence before it can change parsing without touching
   its bytes. After a source-version change, require the current bounded parser
   to recognize the mapped exact item/marker range before writing. If it no
   longer does, or preview is now partial/oversized, visibly refuse. No full
   serialization or extra whole-buffer String is needed for the final
   one-character mutation after this validation.
5. Replace only the middle marker character: unchecked -> lowercase x;
   checked x/X -> ASCII space. Preserve brackets, list marker, indentation,
   numbering, line endings, trailing whitespace and all neighboring bytes.
   One successful toggle is exactly one undo action; undo restores the original
   x/X spelling. Preserve the pre-toggle source selection (and its direction)
   because the edit does not change length. Do not join an existing group.
   Notify Host.Changed once for the toggle, after successful mutation; a prior
   draft Flush has its own ordinary notifications/undo behavior.
6. HTML export emits an inert disabled checkbox with the corresponding checked
   state and existing escaped/formatted label. No script, event handler or
   network asset. Existing partial-document export refusal remains unchanged.
7. Source mode, preview mode and split mode agree after toggle/undo/redo/save;
   original bytes remain unchanged when simply opening/exporting without edits.
   Existing preview size/line/item limits and refusal behavior stay intact.
