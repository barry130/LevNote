## `native/ARCHITECTURE.md`

在「一次性 HTML 与导图 SVG 导出进程」之后新增：

> ## 本地引擎包与选择切换
>
> 引擎包管理只面向固定 catalog 的三个 ID。导入读取一个完整本地发布目录，
> 复制该引擎所需的清单、程序、许可与说明，逐文件验证大小和 SHA256，并把
> 收据写入用户配置目录；不触发执行，也不改变当前选择。启用和重置是
> 显式选择转换：先取消/等待旧导出与预览请求并关闭旧 runner，再持久化
> 新选择并替换运行时。等待期间新任务被阻止；可写草稿、撤销栈和只读源码
> 不被 Flush、Release 或回滚，只读场景会在成功切换后按需刷新。
>
> 这种顺序避免两个危险：一是新引擎与旧请求并存，导致版本/来源身份混用；
> 二是在清理失败时假装选择已切换。清理失败会把引擎服务标记为 poison，
> 阻止后续执行和新的选择转换，但导入与已安装列表仍可用于诊断。若清理
> 失败发生在选择状态已经提交之后，UI 显示实际选择与实际失败，不推断回滚。
>
> 选择状态文件本身损坏时，执行与普通选择转换被阻断，导入/列表仍可用于
> 诊断；「重置全部三个选择」是明确修复出口，只恢复随包选择，不删除已装包。
> 单个已安装包损坏是另一回事：若它正被选中，执行明确失败且不回退随包；
> 列表继续显示健康替代包及其具体问题，显式启用健康包或恢复随包仍可用。
> `Snapshot()` 中的随包状态只声明固定catalog身份和 `bundled` 来源，
> `Version`/`Digest` 为空；实际版本与摘要在运行时验证后出现在导出结果中。
> 校验和是本地完整性检查，不提供发布者认证或进程沙箱。schema1/2/3
> JSON 配置与 worker 包是两套不同机制，不能互相提供可执行能力。

## `native/formats/API.md`

在「固定随包 HTML 与导图 SVG 引擎」内或其后新增「本地引擎包管理」：

- `NewPackageManager(hostDir, stateDir)`：固定catalog入口；已安装包根为
  `stateDir/engine-packages`，每引擎最多12个版本。
- `PackageReceipt` / `PackageStatus`：导入收据与当前选择快照；installed项
  带版本与包摘要，bundled项不预填版本/摘要，实际运行时验证。
- `ImportFromReleaseDir(ctx, releaseDir, engine)`：复制并验证完整本地发布
  目录中的对应引擎，不启用；重复 digest 会重新验证既有安装并原样复用，
  不新增、不覆盖。
- `Installed(ctx, engine)`、`Activate(ctx, engine, digest)`、
  `Reset(ctx, engine)`、`RepairResetAll(ctx)`：分别列出版本、显式启用、
  恢复随包和显式修复全部选择。
- `Snapshot()` / `LoadError()`：非阻塞读取当前状态；选择状态损坏时执行与普通转换拒绝，列表/导入仍可用于诊断。
- 说明选择转换由 app 层负责 join 旧工作、处理 poison 与UI状态；格式包和 runtime API 不接收文件路径之外的任意命令/插件能力。
