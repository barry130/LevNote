## Implemented additive seam

```go
var ErrOutputLimit = errors.New("Markdown HTML output exceeds limit")
func ExportHTMLBytes(doc Document, maxBytes int) ([]byte, []Warning, error)
```

Successful bytes and warnings are identical to the current string API, including
order and source ranges. The returned byte slice is independently owned with
len==cap<=maxBytes. Zero cannot fit the required HTML envelope. A negative limit
is refused as ErrOutputLimit without allocation. Limit refusal returns nil bytes
and nil warnings, never a truncated output. Partial documents still return
ErrPartialDocument and copied parser warnings; partial refusal takes precedence
over the output budget as in current checked export.

Existing ExportHTML/ExportHTMLChecked signatures remain unchanged. They render
once into a strings.Builder through the same emitter, avoiding a new mandatory
byte-to-string copy for existing view callers.

## Implemented algorithm and tradeoff

One shared emitter uses a small internal sink with three destinations: count,
an exactly allocated byte slice, or strings.Builder. The byte API first counts
with overflow-safe remaining-budget checks and no output allocation. If it fits,
allocate exactly once and fill by traversing the already parsed document again.
Warnings are collected only during fill, so they are neither duplicated nor
reordered. Anchors/URL validation are repeated but the parser is not. Count mode
stops on the first limit failure. Every literal/entity append checks remaining
space before writing, including the fill pass.

The five HTML characters escape as literal runs/entities, with the same entity
spellings as today; no whole-fragment EscapeString or large concatenation.
Since escaping cannot shrink text, a raw fragment longer than remaining space
can refuse before scanning. Block/item/table loops stop after sink failure.
Small numeric tags/list attributes may use bounded formatting; no format rules
are duplicated between APIs.

This exact-size approach avoids geometric growth's repeated cumulative result
allocations and worker's whole string-to-bytes copy. It costs a second traversal
and repeats bounded descriptor/anchor/link work. The same-fixture measurement
records that time tradeoff below. It bounds output buffer capacity/generated bytes,
not parser/source allocations, allocator retention or process RSS. No unsafe
string alias, spool file or protocol change.

Worker render delegates to a private renderWithLimit(source, limit), production
always passing engineipc.HTMLMaxBytes. A private serveWithLimit(input, output,
limit) permits a tiny-cap framing regression; production serve passes the fixed
protocol cap. ErrOutputLimit maps to existing output-limit with empty warnings
and zero payload; successful bytes pass directly to WriteResponse. No env/flag
or external budget override.
