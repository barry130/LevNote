# 0010 · 多标签工作区：组合而非改造 DocumentStore

日期：2026-09-29
状态：已采纳
关联：0001（只做桌面端）、0008（范围与排序）

## 背景

P2 结束时产品是**单文档编辑器**：一个窗口装一份文件。`core/document/store.ts` 的注释里
写着一句话：「P1 只开一个文档；多标签在 P2 把它变成数组即可」。

对标产品（horseMD）的核心主张恰好相反：

> 每个文件都作为标签页在同一个窗口里打开，而不是新开一个程序。

这条差异不是「多一个功能」，而是**工作流形态的差异**：单文档意味着
「打开 A → 改 → 保存 → 关闭 → 打开 B」，多标签意味着「在 A、B、C 之间来回跳」。
对一个每天写文档的人来说，后者省下的是几百次「打开/关闭」。

## 决策

**一个标签页 = 一个独立的 `DocumentStore` 实例。** 新增 `core/workspace/store.ts`
（`WorkspaceStore`）负责标签页集合、活动标签页、文件树与偏好，
它**组合**而不是改造 `DocumentStore`。

## 理由

1. **`DocumentStore` 的每条语义都是踩坑换来的。** 脏判定只认内容不看时间戳、
   mtime 当乐观锁、冲突时停下来让用户选、编码与行尾是文件属性（ADR 0003）、
   打开路径上的两道防线（ADR 0009）—— 把它改成数组等于重写这些语义，
   而重写一遍不会比现在这版更对。
2. **组合天然给出「每标签页独立」。** 每份文档有自己的 mtime 基准、
   自己的 savedText、自己的 session 号。改成数组则要在同一个对象里
   维护 N 套这些字段，任何一处漏掉就是串台。
3. **代价是有界的。** 组合的代价是标签页之间不共享撤销栈 —— 而它们本来就不该共享
   （在 A 里按 Ctrl+Z 撤销掉 B 的编辑是灾难）。

## 后果

- `src/core/workspace/store.ts` 成为「多文档」的唯一权威。
- 外壳（`ui/App.tsx`）不再持有任何文档字段，只持有工作区状态与命令上下文；
  文档面板（`ui/DocumentPane.tsx`）自己订阅「我这份文档」。
  这个切分让「加一个标签页」不碰文档语义，让「加一个命令」不碰布局。
