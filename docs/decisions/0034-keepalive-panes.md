# 0034 · 面板常驻：标签页切换保留撤销栈与光标

日期：2026-10-05
状态：已采纳
关联：0010（多标签工作区，本 ADR 兑现它的重审条件）、0021（位置记忆）

## 背景

ADR 0010 的第一步是「切标签页即销毁内核」（`DocumentPane` 以 `activeId` 为 key），
代价写在它的「已知代价」里：**撤销栈、光标、滚动在切换时全部丢失**。
光标与滚动有位置记忆（ADR 0021）兜底成「回到上次离开的大致位置」，
但撤销栈没有任何兜底 —— 用户在 A 里改了十段、切到 B 看一眼资料、
切回 A 按 Ctrl+Z，什么都不会发生，因为内核已经是新实例。

0010 留的重审条件是：先实测「全部挂载 + 隐藏」的内存成本，再决定要不要改。

## 实测（2026-10-05，浏览器 `performance.memory`，N=30 批次采样）

| 场景 | 每空闲实例成本 |
|---|---|
| Markdown 内核（Milkdown，6k 字文档 × 30） | ≈ 0.27 MB（V8 堆） |
| CodeMirror 内核（markdown 语法，6k 字 × 30） | ≈ 1.9 MB（V8 堆） |
| 10 万字 Markdown（× 3，与 6k 字对照） | 空闲时差异在噪声内（≤ 1.5 MB/实例） |
| DOM 节点 | ≈ 87 节点/实例 |

三条实测纪律（比数字本身更重要）：

- **GC 噪声淹没小信号**。N=3 的批次里同场景读数能差 1.7 MB，销毁后的读数（45–49 MB）
  与存活时几乎不可分。结论只能从 N=30 + 最短采样窗口里来。
- **`performance.memory` 只是 V8 堆**，不含 DOM / 渲染器内存。所以数字是**下界**；
  DOM 节点数单独数（87/实例）作为渲染器侧的代理指标。
- **空闲 ≠ 常态**。实测的是「挂上不动」的实例；撤销栈随编辑增长（ProseMirror
  默认 100 个事务深度，CodeMirror 同量级），增长有界但不是零。

## 决策

**访问过的标签页常驻**：每个访问过的标签一个 `PaneSlot`，非活动的整槽 `display: none`；
**没访问过的不挂载**（mount-on-first-activation）。

1. **为什么不「全部挂载」**：会话恢复一次带出十个标签的话，启动就要付十份内核创建的
   时间与内存。而撤销栈只可能在**访问过**的标签里积累 —— 没访问过的标签没有可保留的东西。
   「访问过才常驻」让启动只付活动标签那一份，语义上一点不亏。
2. **内核永远不在隐藏状态下创建**：挂载发生在首次激活那一刻，同一次提交里该槽位是可见的。
   这避开了「在 `display: none` 容器里创建 ProseMirror / CodeMirror 导致测量全 0」的整类问题；
   创建之后再隐藏是安全的（内容重推不需要测量）。
3. **隐藏面板收起一切浮层**（`DocumentPane` 的 `active` prop）：浮层键盘监听挂在 window
   的捕获阶段（硬约束 9），面板藏起来**不会摘掉那些监听** —— 不收起的话，隐藏面板的
   斜杠菜单会截走活动面板的回车。能力标记（`formatting` / `tableOps` / `codeBlockOps` /
   `blockHandleOps`）**不清**：那是内核就绪时交出的能力清单，不是浮层状态。
   同理，隐藏面板**不收浮层类上报**（选区 / 斜杠 / 表格 / 代码块 / 块悬停）——
   外部改写触发内核重报时，收下来的会是一份带着隐藏期间坐标的浮层状态。
   内容与位置的上报不在此列：内容永远是真相，位置按「谁上报记谁」。
4. **句柄与视图信息按面板分桶**：`reportHandle` / `reportViewInfo` 带标签 id，
   进桶，且只有活动面板那一份进入外壳状态。少了这道分发，「关闭一个后台标签」的
   卸载清理（上报 null）会把活动面板的句柄一起清掉 —— 查找栏当场失灵。
   常驻面板被重新激活时内核没有重建、不会重新汇报，所以外壳在 `activeId` 变化时
   **主动从桶里取**。
5. **布局**：`.pane-slot { display: contents }`（槽位不生成盒子，面板的横幅与编辑区
   直接成为 `workspace-main` 的 flex 成员），隐藏走行内样式 `display: none` ——
   行内压过类，只在隐藏时生效，不开「谁赢了看打包顺序」的战场（硬约束 13 的纪律）。

## 后果

- 切标签页不再丢撤销栈、光标、滚动 —— 「切回来就是离开时的样子」。
- 外壳里同时挂着 N 份内核。按实测，几十个标签的空闲成本在几 MB 到几十 MB 之间，
  属于可接受；CodeMirror 文档每实例约 2 MB 是大头。
- 每面板一份的 UI 状态（分屏比例用全局偏好、块菜单等面板内部状态）在切换后保留，
  用户切回来连「面板开着」这个状态都是原样的。
- 位置记忆仍然工作，但它的角色变了：从「切回来的唯一依据」变成
  「冷启动 / 会话恢复时的依据」。

## 重审条件

- **半常驻（LRU 收纳）**：若用户普遍开几十个标签且 CodeMirror 文档占比高
  （每实例约 2 MB），对最久未访问的常驻面板做收纳（销毁内核，保留位置记忆与草稿，
  丢撤销栈）。触发点：真实用户反馈内存占用，而不是拍脑袋。
- **隐藏期间的测量类回归**：内核在隐藏期间无法测量（这是所有编辑器的固有限制）。
  若外部改写 → 隐藏期间重排 → 切回来出现光标/滚动错位的报告，
  考虑在「重新可见」时给内核一次显式的重新测量（而不是回退本决策）。
- **wry / WebView 的 `display: contents`**：桌面端依赖 WebView2（Chromium），
  支持无虞；若将来引入不支持的渲染面，把 `.pane-slot` 改成真实的 flex 容器即可，
  不影响本决策的其余部分。
