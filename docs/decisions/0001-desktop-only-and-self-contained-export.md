# 0001 · 只做桌面端，把「自包含 HTML 导出」提为一等公民

日期：2026-09-28
状态：已采纳

## 背景

最初的需求是「桌面应用 **和** 网页」。评估后收窄为桌面端。

## 决策

1. 只交付桌面应用（Tauri 2）。不做 Web 版，也不做「本地起服务然后用浏览器打开」的形态。
2. 因此**「把成果发给别人」这件事必须在应用内解决**：
   自包含单文件 HTML 导出（内联 CSS 与图片，双击即开）升级为一等公民，在 P2 交付，与 Markdown 渲染同期。
3. 前端代码仍保持平台无关（`DocumentProvider` 是唯一平台差异点），
   这样纯 `vite dev` 下能跑一个内存虚拟盘版本用于界面开发。

## 理由

- Web 版要成立，就必须有服务端来读写用户的文件系统，而那等于把「本地优先」这个最有价值的前提扔掉。
  云同步、冲突合并、权限模型 —— 每一项都是独立的工程，且会稀释「轻」的定位。
- 但砍掉 Web 版会留下一个空洞：**用户无法「发个链接给他看」**。
  空洞不能装作不存在，得用导出补上。
- 保留平台无关的前端，成本几乎为零（一个接口 + 一个内存实现），
  换来的是「改 CSS 不必编译 Rust」，在 P2 做大量界面工作时收益明显。

## 后果

- **代价**：没有实时协作、没有跨设备同步、没有分享链接。
- **收益**：安装包小、无服务端成本、数据 100% 在用户手里、离线和内网环境可用。
- 必须做好的事：导出保真度。导出失败或样式错乱，「没有分享」就从取舍变成了缺陷。

## 重审条件

- 若目标用户里超过半数的主要诉求变成「多人协作编辑同一份文档」，本决策需要推翻。
- 若发现用户实际是把导出文件再手工上传到某个平台，说明缺的是集成而不是 Web 版，
  应优先做该平台的直接发布通道。
