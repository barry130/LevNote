# 0021 · M9 文档位置记忆 + 设置页：位置由内核往返，外壳只负责记

状态：**已采纳**（M9）

## 背景

M9 的交付是两件看着不相干的事，放在一起做是因为它们**共用同一条理由**：
偏好与位置都没有落脚点。

- **位置记忆**：重新打开一份文档，回到上次的光标与滚动。此前每次打开都从第一行开始，
  长文档里这是最刺人的一件事。
- **设置页**：在它之前，主题只能靠 `Ctrl+Shift+T` 循环、侧栏靠 `Ctrl+B`、
  代码块行号藏在代码块右上角的面板里 —— 每一条都是「知道的人才知道」。

它要定下四件事：

1. 「位置」用什么坐标系表达 —— 是内核无关的字符偏移，还是别的什么；
2. 存在哪、存多少条、什么时候丢；
3. 什么时候写、什么时候恢复；
4. 设置页的快捷键一览怎么保证不过期，以及它为什么没有「保存」按钮。

## 决策

1. **`EditorPosition` 里 `offset` 是内核空间的值，外壳只做往返，不解释**
   （`core/editor/types.ts`）。
2. **`textLength` 是一致性凭据**：恢复时内核拿它和当前文档比，**不一致就只恢复滚动、
   不动光标**。
3. **滚动读写放进契约**（`EditorHandle.getPosition` / `setPosition`），外壳不碰 DOM。
4. **位置单独一个存储键**（`qingmo.positions.v1`），与设置分开；**LRU 上限 200 条**
   （`core/positions.ts`）。
5. **内核推、外壳记**（`EditorMountProps.onPositionChange`）—— 外壳不依赖卸载时序。
6. **落盘防抖 600ms，但切文档时立刻结算**（不等防抖）。
7. 设置页的**快捷键表由 `CommandRegistry` 派生**；**没有保存按钮**（每项即时生效）；
   **版本号从 `package.json` 注入**（`import.meta.env.QINGMO_VERSION`）。

## 理由

### 1. 为什么 `offset` 不是「内核无关的字符偏移」

直觉上应该定义成「文档的第 N 个可见字符」，那样外壳就能自己判断这个偏移还有没有意义。
**做不到**，而两个理由都指向同一个结论：

- **Markdown 内核的文档树里没有 `#` 和 `**` 这些标记字符**，所以「第 N 个可见字符」
  与「源码第 N 个字符」之间没有对应关系；
- 要算出「第 N 个可见字符」在文档树里的位置，得**重新实现一遍 ProseMirror 的
  `textBetween` 语义** —— 它在块之间插分隔符的规则并不显然。

第二点是真正的理由。抄一份的下场与硬约束 5 说的完全一样：两份实现在边界情况上
悄悄分叉，而分叉的表现是「光标偶尔跳到别处」，没人会怀疑是这里。

所以契约只要求内核**往返自己的值**。于是 Markdown 内核可以交出 O(1) 的
`selection.head` + `doc.content.size`，代码内核交出 `selection.main.head` +
`doc.length`，兜底内核交出 `selectionStart` + `value.length` —— **三者都是 O(1)**。
`getPosition()` 会在光标每动一次时被调用，O(n) 的写法在大文档上会直接拖慢打字。

### 2. `textLength` 是廉价的近似，代价写清楚

长度变了 ⇒ 文档被改过 ⇒ 那个偏移可能已经不指同一个地方。这个判据**便宜**（O(1)）、
**可解释**，但它确实只是近似：长度相同而内容不同时（比如把「甲乙」换成「丙丁」）
它会误判，光标会落在一个不相关的位置。

接受这个代价的理由是**后果很轻**：位置记忆坏掉的表现是「光标在一个不对的地方」，
而不是丢内容。要更准只能存内容指纹（比如光标前后 32 个字符），
那是另一档成本，见下面的重审条件。

顺带解决了「富文本 ↔ 源码」这一对：两边的 `textLength` 是不同坐标系下的长度
（文档树的内容尺寸 vs 源码字符数），通常对不上，所以切视图后不会拿一套坐标
去另一套里定位。

### 3. 滚动为什么不能由外壳自己存

滚动容器是**内核自己的**：Markdown 是 `.qm-editor`、代码内核是 CodeMirror 的
`.cm-scroller`、兜底内核是 textarea 自身。外壳要自己读写它，就得按类名去认内核画的
DOM —— 那正是硬约束 11 禁止的事。

这是硬约束 11 的**第七次**应用，也是最不像浮层的一次：前六次（选区、斜杠、表格、
代码块、图片、图表）都是「内核报事件、外壳画界面」，这一次是「内核读写状态、
外壳只记住」。

用**比例**而不是像素：像素依赖视口高度与字体，换个窗口大小或改个字号，
同一个 `scrollTop` 指的就是另一段内容了。

### 4. 为什么是内核推，而不是外壳在离开时问一次

外壳想知道位置，最省事的做法是「切标签页 / 关窗口时问 `handle.getPosition()` 一次」。
**不行**：那一刻编辑器可能已经被销毁，而 React 的清理顺序不保证子组件
（真正持有编辑器实例的那一层）还在。依赖卸载时序的东西迟早会在某次重构里坏掉，
而且坏得很安静 —— 表现是「位置记忆有时有效有时无效」。

改成内核在变化时就报上来，外壳只是**记着**，不依赖任何时序。

上报频率**刻意不防抖**：一次上报只读三个 O(1) 字段然后写一个 ref。防抖放在内核里
反而有害 —— 内核的定时器在销毁时不会自动清，得额外维护生命周期。落盘那一侧的防抖
在外壳，因为只有它知道「写一次 localStorage」有多贵。

### 5. 为什么位置不放进设置那个键

两者看着都是「偏好」，但生命周期完全不同：设置是用户**显式**改的、条目固定、
每次改动都值得写盘；位置是**机器**记的、条目随打开过的文件数增长、每次光标停顿都会写。

合成一个键之后，任何一次写位置都会把设置整份重写一遍。而且**坏掉时的代价不一样**：
位置坏了丢掉重记就行，设置坏了会让用户的三套主题偏好一起没。

上限 200 条是必须的：条目只增不减，而配额用尽时 `setItem` 会直接抛。
单条约 80 字节，200 条约 16 KB。

### 6. 切文档时立刻落盘

只靠 600ms 防抖是不够的：用户改完 A 就切到 B、然后进程被杀，A 的位置就没了 ——
而「切走」恰恰是最常见的离开方式，比正常关窗口还常见。防抖是给「连续打字」用的；
**切文档是一个明确的边界，边界上就该结算一次**。

### 7. 设置页的两个「不写」

- **不手写快捷键表**。与命令面板同一条道理：列表由 `CommandRegistry` 派生。
  手写一份的结局必然是某天加了命令忘了补这张表，而**没人会发现** ——
  用户不会去核对设置页里的快捷键是不是全的。
- **不写死版本号**。写死的那个一定会漂（发版时改了 `package.json` 却忘了改界面），
  漂了之后表现是「关于页显示的版本号是旧的」，一个没人会去核对的数字。
  所以从 `package.json` 经 `define` 注入（`vite.config.ts`）。
  > **注入的键必须写成 `'import.meta.env.QINGMO_VERSION'`，不能写成裸标识符。**
  > 这一条是补记的：第一版写的是裸的 `__QINGMO_VERSION__`，`vite build` 与 vitest
  > 都会替换它 —— **单测因此全绿** —— 但 dev server 不替换（Vite 8.3.1 实测）。
  > 结果是**点一下设置整个应用就没了**：渲染到那一行抛 `ReferenceError`，
  > 没有错误边界，React 把整棵树卸掉。
  >
  > 教训有两层，第二层更重要：① 一个纯装饰性的字符串不该换来一个启动期依赖；
  > ② **「测试通过」在这里恰好是误导** —— 替换发生在打包器里，而测试用的是
  > 另一个打包器路径，它比 dev 更「宽容」。**凡是依赖构建期替换的东西，
  > 都要在真正跑起来的那条路径上验一次。**

**没有保存按钮**是因为每一项都即时生效。加了保存按钮反而要回答「点了取消之后
主题回不回去」，而那个问题的答案没人猜得准。唯一的例外是「清除位置记忆」——
它是一次破坏性动作，所以单独放、带确认。

## 代价（实测）

| | M8 之后 | M9 之后 |
|---|---|---|
| 主包 `index-*.js` | 1,734.24 kB | **1,743.31 kB**（+9.07 kB） |
| 单测 | 837 条 / 40 文件 | **880 条 / 42 文件** |

+9.07 kB 里包含设置页的界面、位置存储层、三个内核的位置读写。
设置页**没有**懒加载：它只有一个 chunk 的量级（几 kB），为它加一个异步边界
会引入一次加载态，不划算。

## 重审条件

- **「切视图后位置丢了」成为常见抱怨** → 给 `EditorPosition` 加一个坐标空间标识
  （`EditorModuleId`），只在两边一致时才恢复光标。现在靠 `textLength` 顺带挡住，
  挡不住时后果很轻，所以先不加这个字段。
- **出现「光标偶尔落在无关的地方」的抱怨** → 把 `textLength` 换成内容指纹
  （光标前后各 32 个字符 + 精确偏移）。成本是存储条数减半。
- **200 条不够** → 改成按工作区目录分组，或换 IndexedDB。现在 200 条约 16 KB，
  离任何配额都还很远。
- **设置页继续长大**（比如将来加自定义快捷键录制、自定义 CSS）→ 拆成左侧导航
  的多页结构，而不是继续往单页里堆。
- **位置记忆的写盘成为性能问题** → 现在每次光标停顿一次写，实测无感；
  若大文档下出现可感知的卡顿，改成只写「变化过的」并在空闲时批量提交。
