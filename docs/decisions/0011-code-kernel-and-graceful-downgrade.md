# 0011 · 代码内核用 CodeMirror 6，并把「降级」从「掉到最底」改成「掉到次优」

日期：2026-09-29
状态：已采纳
关联：0004（四类编辑器内核的选型）、0009（Markdown 打开路径的两道防线）

## 背景

ADR 0004 把「代码 / 文本」的内核定为 **CodeMirror 6**，但一直没落地 ——
到 P2 结束，四类内核只实现了 Markdown 一类，其余全走纯文本兜底
（一个白底 textarea）。这意味着产品的一半承诺还没有代码支撑：
对标 Notepad++ 需要的语法着色、行号、缩进、折叠，textarea 一个都给不了。

同时 P2 留下了一个具体的遗憾：**带 YAML front matter 的 `.md` 只能落到纯文本兜底**
（ADR 0009）。当时的说法是「内容不会丢」，但用户拿到的体验是「我的 Markdown
被降级成了一个白板」—— 保住了数据，丢掉了可用性。

## 决策

1. **落地 CodeMirror 6 作为代码 / 文本内核**，按 ADR 0004 的选型执行。
2. **注册表语义修正**：`registerAdapter` 改为「先注册先匹配」，
   与注释一致（原实现用 `unshift`，实际是「后注册先匹配」，与注释相反）。
3. **`core` 内核的扩展名名单刻意包含 `.md` 家族**，作为 Markdown 富文本内核的备胎。
4. **确立「降级到次优」原则**：`canHandle` 否决一个内核之后，注册表继续找下一个候选，
   最终才落到兜底。降级的目标是「能力更弱但**内容安全**的内核」，
   而不是「能力最弱的那个」。

## 理由

- **CodeMirror 6 的架构与我们的适配层契约同构**：不可变 state + 显式 transaction。
  「程序写入」与「用户输入」在模型层是同一件事的不同标注，
  所以 Milkdown 那边踩过的两个坑（回声、假脏）在这里从架构上就不成立。
  见 `modules/code/setup.ts` 的 `SILENT` 注解。
- **第 2 条不是重构洁癖，是一个真实的 bug。** 只有一个内核时看不出来；
  一旦接上第二个认得 `.md` 的内核，错误的方向会让备胎抢在正主前面
  把所有 `.md` 都吃掉 —— 表现为「Markdown 编辑器突然不见了」。
- **第 4 条是这次改动里最有价值的一条。** 它把「四类内核」这个架构的收益兑现了：
  多一个内核不只是多支持一种文件，而是让**每一种降级都多一个更好的落点**。
  实际效果：front matter 文件从「白底 textarea」变成「有行号、有语法着色的源码」。
- **不引入语言包的部分不做。** Go / Java / C++ / Shell 等语言没有装语法包，
  但这个内核**仍然能打开它们** —— 只是没有着色。
  「打开」与「着色」是两件事，不能因为缺一个语言包就让用户打不开文件。

## 后果

- 安装包体积增加（CodeMirror 6 + 10 个语言包，约数百 KB）。
  与 draw.io 的 60–100 MB 相比可以忽略，且完全离线。
- 前端主包从 886 kB 进一步增大。**拆分方案已明确**：
  把 `modules/code` 与 `modules/markdown` 改成 `React.lazy` + `Suspense`，
  外壳首屏能降到百 kB 级。这是 P3 的收尾项，不是现在必须做的事
  （桌面端从本地磁盘加载，与网页端性质不同）。
- `.txt` / `.json` / `.yml` 等文件不再走 textarea，而是走 CodeMirror。
  兜底内核仍然保留，但它现在的职责更纯粹了：**只处理「没人认领」的文件**。

## 重审条件

- 若 CodeMirror 6 出现许可变更或停止维护 → 立即重审（备选：自研 + textarea 增强）。
- 若实测发现「语言包体积」成为安装包的显著部分 → 改用
  `@codemirror/language-data` 的按需加载（动态 import + 代码分割），
  代价是语言要异步到达，编辑器需要处理「语言稍后就位」的时序。
- 若兜底内核的触发率降到接近 0，说明扩展名白名单已经覆盖了真实使用，
  可以考虑把它改成「任何文件都用代码内核打开」—— 但那会削弱
  「任何文件都能打开」这条承诺的可靠性，需要慎重。
