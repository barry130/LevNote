# 0016 · 斜杠菜单：触发判定留在内核，菜单与键盘都在外壳

状态：**已采纳**（M4）

## 背景

M3 的浮层工具条解决了「把已有文字变成加粗 / 标题 / 列表」，但它有个前提：
**得先有字可选**。想从零开始写一份文档，用户还是得自己敲 `# `、`- `、`> `、
` ``` ` 这些语法标记 —— 而这份产品对标的 Typora / Notion 都有 `/` 菜单。

Milkdown 生态里有现成的实现（`@milkdown/plugin-slash`、`@milkdown/components`
里的 slash 菜单）。它们与 0015 里被否掉的 `plugin-tooltip` 是**同一个问题**：
返回内核用原生 DOM 拼出来的元素，样式另起一套，内核开始持有用户界面。

## 决策

**内核只上报「现在是不是在斜杠触发状态、筛选词是什么、菜单该出现在哪儿」，
菜单的渲染、筛选、键盘导航全在外壳。**

具体六条：

1. **契约加两个东西**（`core/editor/types.ts`）：
   - `EditorMountProps.onSlashChange?: (state: SlashState | null) => void`
   - `EditorFormatting.insertBlock(block: InsertableBlock): void`

   `SlashState = { query: string; anchor: SelectionRect }`；
   `InsertableBlock` 是**扁平的字符串联合**
   （`'paragraph' | 'heading1' | … | 'hr'`），不是 `{ block, level }` 那种结构 ——
   `heading1` 与 `heading2` 是两个不同的条目，不是同一个条目加不同参数。

2. **与 `onSelectionChange` 分开，不合成一个回调。**
   两者的生命周期差得很远：选区每次移动都变，斜杠只在「空段落里打了 `/`」
   这个很窄的条件下出现。合成一个的话，外壳每次移动光标都要重新判断要不要收菜单。

3. **触发条件收得很紧**（`modules/markdown/selection.ts` 的 `describeSlash`），
   四条缺一不可：光标塌缩 · 所在文本块是段落 · 光标停在文本末尾 ·
   整段匹配 `/^\/(\S*)$/`。
   **不允许筛选词里出现空格**是刻意的：允许的话，用户写「一半 / 另一半」这种正文时
   会莫名弹出菜单 —— 那种「你以为在打字，它以为在选命令」的干扰比少一个功能烦人。

4. **`insertBlock` 与 `toggleBlock` 分开，因为前者多一件事要做：先删掉 `/query`。**
   删文字和套块格式必须由内核在**一次调用**里完成 —— 要删哪几个字符是文档坐标，
   只有内核知道。外壳不该也不能自己算。

5. **菜单锚在「段落内容起点」而不是光标处。** 光标会随着筛选词变长一直往右跑，
   菜单跟着飘会很难看。

6. **键盘处理挂在 `window` 的捕获阶段**（`SlashMenu.tsx`）。菜单打开时焦点仍在
   编辑器里，ProseMirror 的 `handleKeyDown` 挂在 `view.dom` 上、在冒泡路径上**先到**；
   默认方式监听的话，我们收到 Enter 时段落已经被拆开了。

## 理由

### 为什么 Esc 只收菜单、不删用户打的字

删掉 `/表` 也能解决「菜单立刻又弹回来」这个问题（`/表` 还在文档里，触发条件仍然成立），
而且 Typora 就是这么做的。但那样意味着**一次 Esc 会改文档内容** ——
用户只是想「算了不插了」，不该付出这个代价。

所以改成记住「哪一段筛选词被收起过」（`SlashMenu` 里的 `dismissed`）：
筛选词没变就不再显示，用户接着打字菜单自然回来。一个字符都不丢。

### 为什么「一个匹配项都没有」时回车要放过

菜单拦住回车是为了「回车 = 插入高亮项」。但一个匹配项都没有时，拦下回车就成了
**「按了没反应」** —— 而用户打 `/zzz` 有两种可能：想搜一个不存在的块，
或者就是想把 `/zzz` 当正文打出来（后者更常见）。

所以没有匹配项时 `SlashMenu` 直接放行：ProseMirror 拆开段落，新段落是空的，
触发条件不再成立，菜单自己收起来。Esc 那条路不受影响（它永远是「收起菜单」）。

### 0015 的重审条件 3 在这里有了答案：**共用了骨架，没有共用组件**

0015 留了一条：M4 也需要浮层时，看能不能把定位逻辑抽成共用的 `FloatingLayer`。

实际做下来，**上报那一侧真的共用了**：`plugin.ts` 里的
`floatingReporterPlugin<T>(key, read, getReporter)` 把「取回调 → 合并到帧 → 跟滚动 →
选区/storedMarks/文档三者任一变化就重报」这套骨架收成一个泛型函数，
选中工具条与斜杠菜单各只提供自己的 `read`。这是有意义的复用 ——
两处的机制确实一模一样，分开写迟早只给其中一处修 bug。

**但渲染那一侧没有抽。** 两个浮层的摆放规则是**相反**的：
工具条默认摆在选区**上方**（下方是用户正在看的内容），斜杠菜单默认摆在光标**下方**
（上方是刚才打的那一行）。硬抽成一个组件，参数表会变成
「默认在上还是在下 + 是否带输入框 + 是否响应键盘 + 是否记住收起状态」，
读起来比两份各自 100 行的实现更难。

判断依据：**共用的部分如果是一组「机制」，就抽；如果是一组「开关」，就别抽。**

### 为什么 `InsertableBlock` 用扁平字符串而不是 `{ block, level }`

菜单项本身需要一个稳定的 id —— 做 React `key`、做筛选、写测试都要它。
而「标题几级」是菜单项**身份**的一部分，不是它的参数。写成 `{ block: 'heading', level: 2 }`
之后，`heading1` 与 `heading2` 就变成了两个由数据决定的项，
`SLASH_ITEMS` 表里也再没有一处能一眼看出「一共有几个可插入的块」。

## 代价

### 1. 插入出来的块是**空的**

选了「一级标题」之后文档里是 `# `（空标题），`/表` 那三个字被删掉了。

这是对的（`/表` 是命令不是内容，Typora 同样如此），但值得写明：
它意味着斜杠菜单**不会**把用户打的字变成新块的内容。

### 2. 空容器会序列化成 `<br />`（M4 暴露出来的既有行为）

在空段落里插入引用 / 列表之后立刻保存，文件里是 `> <br />` / `* <br />`。

来源已经查清：Milkdown 的 `remarkPreserveEmptyLinePlugin` 把空段落序列化成一个
`<br />` 的 **html 节点**当作**空行占位符**。没有它，mdast 里「一个空段落」
序列化出来什么都没有 —— 存盘再打开，那个空引用就消失了。

所以这是**刻意的**，而且**往返稳定**（`> <br />` → `> <br />`）。
它只影响「插入了但一个字没打就保存」，一旦打字（`> 甲`）占位符就没了。
同样的产物在 M4 之前就能造出来（手敲 `> ` 触发输入规则），**不是 M4 引入的**。

不关掉那个插件的理由：关掉就等于放弃空行保留，那是更常见、更烦人的问题。
已记进 `../open-decisions.md` 待观察。

### 3. 点到编辑器之外，菜单不会自己收起来

与 0015 的代价 3 同一条，原因也相同（内核只在**选区真的变了**时上报）。
斜杠菜单还多一层：点别处不会让 `/表` 消失，所以触发条件仍然成立。

### 4. 菜单的几何只能靠人眼看

同 0015 的代价 4。jsdom 没有布局引擎，`getBoundingClientRect()` 全是 0，
所以测试只能钉住「该出现时出现了、内容对不对、键盘走没走到」，
**摆在哪、会不会被视口边缘切掉，只能靠真机确认**。

### 5. 逐字打字的测试脚手架

斜杠触发是逐键推进的，直接构造一个 `/表` 的文档会把「敲到第几个字时菜单出现」
整段跳过。所以新增了 `src/test/typing.ts`：改 DOM 文字 → 让出一个宏任务让
`MutationObserver` 记进队列 → 派发 `input` → 等一帧。它复现了浏览器里的真实链路
（而不是绕过它直接塞事务），代价是比直接构造状态慢，而且只支持 ProseMirror。

## 重审条件

1. **用户反馈「菜单在正常打字时自己冒出来」** → 说明 `SLASH_TRIGGER` 太松。
   先收紧触发条件（比如要求 `/` 前是行首或空白），**不要**改成「只在行首触发」——
   那会让「在段落中间插一个列表」变得做不到。
2. **`> <br />` 被反复反馈成「保存后文件里多了垃圾」** → 关掉
   `remarkPreserveEmptyLinePlugin`（代价：空行不再保留），
   或者改成序列化时把**只有占位符**的容器整个省掉（代价：空引用存盘后消失）。
   两条都有真实损失，所以现在不动。
3. **可插入的块超过 ~15 项，或者需要「表格 / 数学公式 / 图片」这类带参数的项** →
   扁平字符串的 `InsertableBlock` 会开始撑不住（`table3x3` 这种 id 是信号）。
   那时改成 `{ kind, params }`，并在菜单项上加一个二级输入。
4. **换掉 Milkdown** → 契约里只有外壳自己的词（`SlashState` / `InsertableBlock`），
   换内核只需要重写 `describeSlash` 与 `insertBlock` 的派发，外壳一行都不用改。
   **做不到就说明这次抽象失败了**，要在这里如实记下来。
