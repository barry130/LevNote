# 0031 · i18n 骨架：先抽文案，不急翻译

日期：2026-10-04
状态：已采纳（P3 第 17 项落地）
关联：0012（命令注册表 —— 首批文案的宿主）、`core/i18n/`、
`ROADMAP.md` 第 17 项（「越晚做越贵」是这项排进 P3 的理由）

## 背景

ROADMAP 把 i18n 定位成**骨架**：「先抽文案，不急翻译」。要回答的是：

- 骨架到底要立起什么（机制、约定、首批范围）；
- 什么**现在不做**（不引入 i18n 库、不在设置页放语言切换、不翻第二语言）。

## 决策

### 1. 机制：`core/i18n/` 三件套 —— 目录、查表、插值

- `messages.ts`：`zhCN` 目录（`as const`），`MessageKey = keyof typeof zhCN`
  —— **写错 key 是编译错误**，不是运行时空白。
- `index.ts`：`t(key, params?)` 查表 + `{name}` 插值；`setLocale` / `getLocale`
  管语言状态。回退链：**当前语言 → zh-CN（key 定义处）→ key 本身**。
  最后一级返回 key 而不是空串是有意的：目录漏了 key，屏幕上是可搜的标识，
  不是无声空白（硬约束 2 的 i18n 版）。
- 插值漏参的占位符**原样保留**，不悄悄删掉。

不引入 i18n 库：骨架只需要「查表 + 插值 + 回退」，四十行以内；i18next 的
复数规则、日期格式化、懒加载命名空间在只有一种语言时全是死重。

### 2. 首批文案：命令面（title + category）

23 条命令的标题与 6 个分组，全部收进目录（`command.<id>.title` /
`command.category.<域>`）。选命令面的理由：命令清单是**能力的唯一清单**
（ADR 0012），命令面板、活动栏提示、设置页快捷键表都从它派生 ——
一处抽完，所有派生 UI 自动跟上，且 `registry.test.ts` / `App.test.tsx`
钉住值不变（**抽文案不许顺手改文案**）。

### 3. 明确不做的

- **keywords 不进目录**：拼音助记（'baocun' 等）是 zh-CN 特有的检索辅助，
  不是显示文案；第二语言需要不同助记时再收。
- **语言偏好不进设置页**：只有一份目录的今天，放一个语言切换只会做出
  「切了没反应」的死设置 —— 那是另一种静默撒谎。设置页接入点留给第二份
  目录落地的那次改动（`registerBuiltInCommands` 在 App 启动 effect 里调用，
  在它之前 `setLocale` 即可，顺序是现成的）。
- **Rust 侧错误文案不动**：错误横幅出现在 UI 层时自然会被看到，届时按需
  收进目录；现在抽了也验证不了。

## 后果

- 加第二种语言的工作量变成：复制一份目录 → 逐 key 翻译 → `SupportedLocale`
  扩联合类型 → `CATALOGS` 加一行 → 设置页加偏好项。机制本身不用再动。
- `Command.title` 是**注册时求值**的字符串（不是惰性取值）：当前语言恒定
  所以无感；第二语言落地时如果运行中切换语言，命令标题要么重注册、要么
  title 改成惰性 —— 见重审条件。

## 重审条件

- **第二语言真的立项时**：评估 i18n 库（复数、日期、RTL 需求是真的才引入）；
  同时补「部分翻译目录的回退链」测试（现在的测试留了位置，见
  `i18n.test.ts` 的 locale 状态 describe）。
- **运行中切换语言**：若成为需求，`Command.title` / `category` 改为惰性取值
  （函数或注册表在展示时查表），并重审命令重注册的语义。
- **命令 id 改名**：key 随 id 走（`command.<id>.title`），改名是跨两处的
  编译期可见改动 —— 这是刻意的，不要为省事把 key 与 id 解耦。
