# 0032 · 自定义快捷键：录制 + 冲突显式顶掉

日期：2026-10-04
状态：已采纳（P6 第 31 项落地）
关联：0012（命令注册表）、`core/commands/keybinding.ts`（解析与匹配）、
`core/commands/registry.ts` 的覆盖表、`core/settings.ts` 的 `keybindings` 字段、
`ROADMAP.md` 第 31 项

## 背景

快捷键一直写死在命令定义里（ADR 0012），设置页那张表是**只读**的一览。
「自定义快捷键」要补的是三件事：怎么录、怎么判断冲突、改完存哪。

## 决策

### 1. 录制 = 捕获一次按键 → 规范写法

`specFromEvent(event, platform)` 把录到的 `KeyboardEvent` 变成 `Mod+J`
这类规范写法（与内置定义同一套语言，`parseKeybinding` 能原样吃回去）。
只按修饰键返回 null —— 录制还在等键名。修饰键顺序固定（Mod → Win/Ctrl →
Alt → Shift → 键名），单字符键存大写。

**安全闸**：裸字母 / 数字键不允许录（`isSafeGlobalSpec`）—— 它们在输入框里
会被打字占用（`isAllowedInEditable` 白名单的同一条理由），录进来就是
「设置完打不了字」。当场说明原因，不靠保存后的惊讶。

录制监听挂 `window` **捕获阶段**（硬约束 9 的同一套理由），`preventDefault`
+ `stopPropagation` 让录制期间的全局快捷键失效 —— 否则录 `Mod+S` 的那一刻
文档先被保存了。

### 2. 冲突不阻止，**显式顶掉**

「阻止保存」会让用户绕不出死胡同（想用的键被一条不常用的命令占着）；
「静默共享」会让两个命令抢同一个键。做法是第三条：保存时把原占用者的
快捷键**显式置空**（覆盖表里写 `''`），冲突在确认前说出来
（「命令乙当前也用这个组合键 —— 保存后它将显示为未设置」）。

占用的判定按**解析后的字段**（`findOwnerOf`），不是字符串比对 ——
`Mod+Shift+S` 与 `Shift+Mod+s` 是同一个快捷键。

### 3. 覆盖表是三态的，存进偏好

`ViewSettings.keybindings: Record<命令 id, string>`：

| 状态 | 含义 |
|---|---|
| 键不存在 | 用内置默认 |
| 值 = 写法 | 覆盖成这个写法 |
| 值 = `''` | **显式清除**（这条命令没有快捷键了） |

三态缺一不可：被顶掉的命令若悄悄回到默认值，它会继续响应 —— 那是用户
以为已经关掉的东西还在起作用，另一种静默。显示交给 `formatKeybinding`，
偏好里不存排版好的字符串（平台相关，`⌘` vs `Ctrl`）。

注册表侧是**整表替换**的 `setKeybindingOverrides`（与文件监视 ADR 0029
同一条形状哲学：幂等，调用方不用记现在生效的是哪几条），替换后解析缓存
整体作废。App 里一个 effect 把 `settings.keybindings` 推给注册表，
设置页只改偏好、不碰注册表 —— 与其它偏好项同一条数据流。

### 4. 设置页：每一行都可改

旧表的「没有快捷键的命令不进表」原则随之废止：每一条命令都可被指派
快捷键（原本没有快捷键的命令显示「未设置」），显示不出来就永远指派不了。
改过的行出现「恢复默认」—— 它也走同一条冲突流程（默认写法可能已被
别的命令覆盖占用）。

## 后果

- 设置页的快捷键表从「一览」变成「一览 + 编辑」，仍是命令注册表的派生物，
  不存在第二份清单。
- `Esc` 在录制中是「取消录制」；设置页自身的 Esc-关闭监听在录制时让路
  （两个监听同为 window 捕获，靠显式检查让路，注释里写明了原因）。

## 重审条件

- **多绑定（chord）**：`Mod+K Mod+S` 这类两段式快捷键现在的模型表达不了
  （一个命令一个写法）。有真实需求时改覆盖表值为写法数组，录制成两步。
- **按作用域区分**：现在是全局快捷键。若出现「编辑器内 / 面板内各自一套」
  的需求，覆盖表要加作用域维度，而不是复用全局这张表。
- **恢复默认引发二次冲突**：恢复默认时顶掉别人的行为与录制保存一致；
  如果实测里「恢复」比「新改」常见且误顶频繁，考虑给恢复也加确认。
