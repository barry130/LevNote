# 0025 · 导图内核接入（`EditorAdapter` 的第三个实现）

日期：2026-10-02
状态：已采纳（P4 第 22 项落地）
关联：0007（导图内核选 mind-elixir）、0014（源码视图不注册进注册表）、0022（视图三态）、
`format-spec.md` §7.1.2

## 背景

`.mindmap` 的文件层（P4 第 21 项）已经落地：`core/mindmap/` 是纯函数，
`.mindmap` ⇄ 内存树，47 条测试钉住。第 22 项要把它接到应用里 ——
这是**四类一等公民里第一个非 Markdown 的格式**，也是适配层契约第一次被
「另一种数据形状」检验。

验收目标不是「导图功能齐全」，是「导图这一类文档能作为一等公民读写与编辑」：
打开、改、保存、不丢数据、坏文件有交代。

## 决策

### 1. 注册顺序：`markdown` → `mindmap` → `code`

代码内核认得 `.md` **和** `.mindmap`（它是两者的源码形态）。所以它**必须排在最后**。

**这条在实现时踩过一次**：第一版按「markdown → code → mindmap」注册，
于是 `codeAdapter.matches('图.mindmap')` 先命中、它又没有 `canHandle`，
所有 `.mindmap` 都被代码内核吃掉，导图内核一次都没被调用。
`wiring.test.ts` 的备胎链测试当场抓住。

### 2. `canHandle` 的三道守卫，退路是**代码内核**而不是纯文本

否决的三种情况：

| 情况 | 为什么否决 |
|---|---|
| 不是合法 JSON / 缺 `root` / `format` 不对 | 没有树可画。硬接下来用户看到一张空白画布，连内容在哪都找不到 |
| 节点 id 里有 `"` 或 `\` | 内核的 `findEle` 是 `querySelector('[data-nodeid="me' + id + '"]')`，那些字符让选择器语法错误 |
| 节点 id 重复 | `querySelector` 只返回第一个 —— 用户拖第二个节点动的是第一个，**界面上没有任何提示** |

**不在适配层里修 id，而是如实拒绝**：id 是旁表的键（`arrows` / `summaries`
都按它引用节点），换掉 id 就得同步重写那些引用，写错的后果比降级严重。

退到代码内核意味着用户拿到的是一份**有 JSON 着色**的源码，能直接改；
退到纯文本则是白底 textarea。所以 `.mindmap` 同时进了 `CODE_EXTENSIONS`
与 `languageForPath` —— 与 `.md` 的处理完全同构。

### 3. `layout` 是四个取值，对应内核的四个方向

`Ctrl + 方向键` 就能换布局（内核自带的键位）。只认一个值等于
「用户按了 `Ctrl+←`、保存、再打开，方向回去了」—— 一次静默的数据丢失。

| `layout` | 内核 `direction` |
|---|---|
| `logicalStructureLeft` | 0 |
| `logicalStructureRight` | 1 |
| **`logicalStructure`（默认）** | **2（双向）** |
| `orgChart` | 3 |

**默认刻意不是内核的默认值**（内核是 1，全部向右）：打开一张 `.mindmap`
该看到的是中心发散，不是一张左对齐的树。

顺序**必须**与方向编号一致 —— 适配层用下标查表，顺序错了只会让
「向右」显示成「向左」，没有任何地方会报错。`adapter.test.ts` 用一条测试钉住它。

### 4. 节点的 `direction` 走 `extra`，但「基准」取内核稳定之后的那一份

内核跑完第一次 `layout()` 会给每个顶层节点补 `direction`（0 在左 / 1 在右，
按左右计数均分）。它是**确定性的产物**，但毕竟不在用户的文件里。

于是有一条**顺序要求**：「没改过就不写」的基准必须取 `init()` 之后
再 `getData()` 一次的那份，不能取刚解析出来的那份 —— 否则内核补上的
`direction` 会被当成「用户改了东西」，表现是**打开文件什么都没做，
`getValue()` 就交回一份多出字段的文本**。

吸收进基准之后两件事同时成立：「打开 → 保存」逐字节一致；
用户的左右分布**能存下来**（它留在 `extra` 里，`toKernelData` 时交回内核）。

> 这是本项唯一一处「看起来多余的代码」。`MindmapEditor.tsx` 里那个 `settled`
> 变量就是它 —— 删掉它，`MindmapEditor.test.tsx` 的保真度用例立刻变红。

### 5. 源码视图就是代码内核 → 自动获得视图三态

`.mindmap` 的源码形态就是 JSON，而轻笺已经有一个 JSON 编辑器。
与 Markdown 那边是**同一条依赖**（markdown → code），理由也一样：
它描述的是「导图的源码形态由代码内核呈现」，而不是「代码内核知道导图」。

外壳只问 `sourceView` 在不在，所以导图**自动**有了富文本 / 源码 / 分屏三态，
`DocumentPane` 一行都没改。

### 6. `toHtml()` 返回 `null`（诚实降级）

导图没有能进导出文档的「语义 HTML」—— 它的呈现是一张由绝对定位的 div
与 SVG 组成的图。返回 `null` 是**契约允许的合法结果**：自包含导出会退回用
`<pre>` 呈现 JSON 原文并如实说明，而不是伪造一份「看起来像图」的 HTML。

真要做富导出，正解是内核的 `exportSvg()`，那要处理 `foreignObject` 的兼容性
与样式内联 —— 是另一个决定，不在「接入内核」的射程内。

### 7. 查找：逐节点匹配，只搜 `topic`

不拼成一篇大文本：那会产生**跨节点的匹配**（A 结尾的字符 + B 开头的字符），
而那一处在界面上根本不存在。逐节点查还顺带解决了偏移映射 ——
每个匹配的偏移天然就是它所属节点的段内偏移。

不搜 `note`：内核**不渲染** `note`（它在数据里，界面上看不见）。
搜一个用户看不见的东西，会得到「找到 3 处，但一处都看不到」。

### 8. 不实现 `getPosition` / `setPosition`

内核的「滚动」不是原生滚动，是 `transform: translate3d` 的平移 ——
`readScrollRatio` / `applyScrollRatio` 那对纯函数对它不适用。
不实现是**契约允许的**：外壳不做位置记忆，而不是记一个假的位置。

### 9. `readOnly` 是**三件套**，不是 `editable: false` 一件

`editable: false` 只管拖拽与新建；`contextMenu` 管右键菜单；
`keypress` 管 F2 / Enter 这些进编辑态的键。

**编辑节点文字的唯一入口是 `keypress`** —— `editTopic` 本身不检查 `editable`
（读过 `MindElixir.js` 确认：它没有 `dblclick` 监听，只有 F2 那条路）。
所以少关一个就能改到内容。

### 10. 同步 `import`，**不**懒加载

与 M7（katex 258 kB）/ M8（mermaid）的取舍**刻意不同**：

- katex / mermaid 是**文档内的元素** —— 同一份 Markdown 里可能有也可能没有，
  所以按需加载是对的；
- 导图是**另一种文档** —— 打开 `.mindmap` 就一定要它，没有「加载了但用不上」的情况。

代价是主包 +116.59 kB（1,756.20 → **1,872.79 kB**，gzip 620.69）。
本地应用里这是几毫秒的解析成本，换来的是一条同步的挂载路径
（不需要 `disposed` 竞态处理、不会闪一下无样式的图）。

**重审条件**：主包继续膨胀到用户能感知（判据：冷启动首屏 > 300ms），
或导图内核体积再涨一倍。

## 后果与必须注意的坑

1. **`matchMedia` 在 jsdom 里不存在**，而内核在**构造函数里**就调它两次
   （`prefers-color-scheme` 与 `(hover: none), (pointer: coarse)`）。
   缺了它导图根本创建不出来，而错误走 `onError`、表现是「导图打不开」——
   看起来像产品坏了。已补进 `src/test/jsdom-gaps.ts`。
2. **空文件的「原文」是 0 字节**，不能当「没改过就交回原文」的回退目标 ——
   那等于「打开一份空白文件、看到一张图、保存后图没了」。
   组件里 `originalText` 在空文件时是 `null`。
3. **`theme` 与 `compact` 保留在 `extra` 里但不与内核交换**。
   它们是视图偏好（ADR 0021）。交换会让「深色主题下打开一张图突然变亮」，
   而反向写回会覆盖用户手写的那一份。**保留但不读**是唯一同时满足两边的做法。
4. **`nodeData` 是活对象，顶层不是**。`getData()` 返回的是一个写死的字段列表，
   我们展开到它上面的自定义顶层键会原样消失 —— 所以顶层 `extra` 必须
   从上一份信封继承，节点层的 `extra` 才是现读的。这个不对称是有原因的。
5. **主包 +116.59 kB**，见上面第 10 条的重审条件。

## 放弃的方案

- **在适配层里净化节点 id**：会破坏 `arrows` / `summaries` 的引用，见决策 2。
- **把 `layout` 收窄成一个值**：会丢掉 `Ctrl + 方向键` 这个用户动作，见决策 3。
- **`toHtml()` 用 `exportSvg()` 画一张 SVG**：`foreignObject` 的兼容性与样式内联
  是另一个量级的工作，而且导出的 SVG 在别的渲染器里未必显示得出来。
- **懒加载内核**：见决策 10 的对比。
- **实现位置记忆**：内核的滚动不是原生滚动，见决策 8。
