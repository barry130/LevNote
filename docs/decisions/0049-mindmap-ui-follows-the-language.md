# 0049 内核自己画的字也得跟着语言变 —— 切语言当场重建

- 状态：已采纳
- 日期：2026-10-14
- 关联：硬约束 2、3、11；[ADR 0031](./0031-i18n-skeleton.md)（目录里各留一处）、[ADR 0047](./0047-words-that-outlive-the-language-switch.md)（`t()` 的结果跨不跨渲染）
- 承接：[ADR 0048](./0048-mindmap-and-drawio-are-first-class-too.md) 里「另外两类文件也是一等公民」之后，用户提的第一件事

## 背景

用户说：「思维导图里面内容换成中文。」

拆开看，导图面板上有两类文字，来源完全不同：

| 来源 | 谁画的 | 中文吗 |
| --- | --- | --- |
| 主题文字、展开标记、右下角工具条图标 | 内核，但**内容**来自文件 | 是（文件里就是中文） |
| 右键菜单十一条、新节点的占位文字 | 内核自己写死的 | **否**，一直是英文 |

第二类只有两处，都在 `mind-elixir` 5.15.1 里，都有构造参数可配，但形态完全不同：

1. **右键菜单**。`src/modules/mindmap/MindmapEditor.tsx` 原来传的是 `contextMenu: !readOnly` —— 布尔 `true`。
   `dist/MindElixir.js:1382-1388`：`function Xn(e, t){ const n = {focus:!0, link:!0, locale: Yn}; t = t===!0 ? n : Object.assign(n,t); … }`
   传 `true` 时 `locale` 落到**硬编码的英文包** `Yn`。传对象才能带上自己的语言包。
2. **新节点占位**。`dist/MindElixir.js:2865` `this.newTopicName = h || "New Node"`，
   选项 `Options.newTopicName?: string`（`dist/types/types/index.d.ts:109`）。

浮动的缩放工具条**不是**这一族：`dist/MindElixir.js:1525-1531` 画的四个条目全是 SVG 图标，没有文字。

用户接着说：「需要 / 希望连切语言当场生效一起做。」所以本轮要的不是「换成中文」，是「换成中文，而且换的时候立刻生效」。

## 判据

内核把右键菜单在**安装那一刻**就建成了 DOM：

```js
// dist/MindElixir.js:1393-1394
E.id = f, E.innerHTML = `<span>${be(b)}</span><span ${w ? 'class="key"' : ''}>${be(w)}</span>`
```

文案在那行 `innerHTML` 赋值时就烤死了。所以「换了语言包对象」对已经建好的菜单**毫无作用** ——
只能重建内核。这条是本轮所有设计的起点，也是它把问题从「改几个字符串」变成「改一次生命周期」的转折。

于是「切语言当场生效」只有一条路：**订阅语言变化 → 重建内核**。

## 取舍

### 1. 订阅放在组件里，不等外壳那一圈

用 `useSyncExternalStore(subscribeLocale, getLocale)`，把 `locale` 放进主 `useEffect` 的依赖数组。

不靠 `src/ui/App.tsx` 那个 `localeTick` 顺带把内核刷一遍，有两条理由：一是内核不该依赖父组件有没有重渲染（那是一条看不见的耦合）；二是 `useSyncExternalStore` 保证读取一致、不撕裂 —— 这在一个「重建会销毁再创建内核」的组件上不是小事。

这是全项目**第一处**真的订阅语言变化的消费方。在此之前每个界面都在渲染那一刻现取 `t()`，所以切语言不需要谁通知它们；这里因为要重建，才第一次需要通知。

### 2. 自建语言包，不用内核自带的 `cn` / `en`

`mind-elixir/i18n` 是 `package.json` `exports` 里的**公开入口**（`:53-56`），导出十七种语言，直接引一份最省事。没引，两个理由：

- **口径**。内核自带的 `cn` 写「插入子节点」；本项目从头到尾管 `topic` 叫「主题」（`core/mindmap/template.ts` 的 `emptyMindmapDocument('中心主题')`、解析器的错误提示都是这个词）。同一屏里同一概念两种叫法，比措辞不够地道更伤。
- **一个真相来源**。用户可见的字符串按 ADR 0031 只在 `core/i18n/messages.ts` 里。从第二个地方取词，等于给「切语言到底生没生效」开一个不受测试覆盖的口子 —— 那是 ADR 0031 在命令面（`BUILT_IN_COMMANDS` 的 `title`）已经踩过的坑。

代价是十三对字符串要自己维护。换来的是：换语言这件事只有一个开关，测它只需要测一处。

### 3. `mindmapLangPack()` 是函数，不是模块级常量

模块级 `const PACK = { addChild: t('…') }` 会在模块被求值那一刻烤死语言 —— 正是 ADR 0031 记过的那个坑的翻版。现查表，于是「什么时候调」就是「语言什么时候生效」。

### 4. 重建不许丢内容：`latestRef`

重建时最自然的写法是拿 `initialValue` 重新解析。那会让用户在这份文件上已经做的修改**静默回滚**：界面还画着改过的图，一保存就弹回打开时的样子。

所以加 `latestRef`，约定只有一条：**任何时刻它都等于「此刻 Ctrl+S 会写出的内容」**。由 `emit()` / `setValue()` / `getValue()` 三处维护，重建时拿它当种子。

不在 cleanup 里调 `getValue()` 来补这份种子：那样要包 `try/catch` 兜异常，而吞掉它就是开一个静默的洞（硬约束 2）。三处维护是纯数据代码，跑在每次用户操作上，不引入新的异常路径。

### 5. `getValue()` 里记的是「交出去的那个值」，不是 `lastText`

这是本轮最容易被写错、后果最安静的一处。

`lastText` 是**规范形式**的序列化结果，`originalText` 是用户文件里的原始字节串。两者可能不是同一串字��（用户把 JSON 手工压成了一行、或者缩进不是两个空格）。

`getValue()` 在用户没动过时交回 `originalText`。如果顺手把 `lastText` 记进 `latestRef`，那么：切一次语言 → 种子变成规范形式 → 下一次保存把用户的文件**重排版**。
界面上看不出任何异常，而「打开 → 保存逐字节一致」这条（ADR 0048 复评时逐字节验过的）当场破掉。

所以记的是那个 `result`。这条被一条用例单独钉住（用例名字里就写着「种子不能被规范形式污染」）。

### 6. 兜底通道的窗口要在 cleanup 里结掉

重建的 cleanup 里如果还挂着一个待办的防抖比对（`linkDiv` + 300ms），那说明用户拖完节点 300ms 内就切了语言，那份改动还没进 `latestRef`。

不结掉的后果：「拖一下、切语言」丢掉那一下。所以 cleanup 里先 `clearTimeout` 再 `emit()` —— 用每次用户操作都在跑的同一段纯数据代码，不是 `getValue()`。

代价要说清楚：切语言本身**可能**触发一次 `onChange`（只在那个 300ms 窗口里）。那是**真实发生过的一次编辑**，标脏是对的 —— 拖了没保存，本来就该标脏。

### 7. 缩放要还原，选中项不还原

`init()` 收尾会 `toCenter()`。不还原缩放，「切一次语言视口就跳一下」，用户会以为自己的图变了。所以 cleanup 里记 `scaleRef.current = mind.scaleVal`（公开字段，`dist/types/index.d.ts:68`），新内核 `init()` 之后 `mind.scale(scaleRef.current)`。

折叠状态不用管：它在文档数据的 `collapsed` 里，重建后自动回来。

**没保住的三样**：选中项、专注模式、平移位置。它们都不是公开 API，重建后回到初始状态。抄内部状态来保是另一回事（撬实现细节、升级即烂），本轮明确不做。

## 后果

- 导图内核从「挂载时建一次」变成「挂载时建一次 + 语言变了再建一次」。`find` 的调用方需要能处理句柄被换掉 ——
  外壳那条链本来就有：`handleEditorReady` → `App.tsx` 的 `reportHandle` → `setHandle(next)` → `FindBar` 拿到新 `search` 自动重跑查找
  （`src/ui/FindBar.tsx:59-60` 的注释早写明「切标签页会换一个内核实例」）。
- 一处新的订阅者。全项目订阅语言变化的消费方从此是 1 个而不是 0 个。
- 新增十三对文案，落在 `ui.mindmap.*`。它们的使用点只有一处（`lang-pack.ts` 的十二个 + `newTopicName`）。

### 测到的（`src/modules/mindmap/MindmapEditor.test.tsx` 新增 6 条）

- 右键菜单是中文的，且「连接」那两条也在（传对象时 `focus` / `link` 两组要显式打开，漏一个就少两条菜单项）；
- 切语言之后菜单当场变英文，**不必关掉重开文件**；
- 切语言不丢内容：改过的图重建后还在，保存写出去的也是那一份，且重建交的是**新**句柄；
- 切语言不把没改过的文件变成改过的：`changes` 为空、`getValue()` 仍逐字节等于原文；
- 保存过一次（拿一份**非规范形式**的文件）再切语言，仍逐字节一致 —— 即第 5 条取舍；
- 只读时根本没有右键菜单：换成对象传参之后这条没松。

另有 `src/modules/mindmap/lang-pack.test.ts` 三条（十二个键一个不少、每条都取自目录、现查现变）。

**没有测到的，如实写出来**：

- 缩放还原 —— jsdom 没有布局引擎，缩放值永远是 1，测了只能得到一条假绿的测试。只能靠 `pnpm run tauri dev` 里的人工冒烟。
- 第 6 条那个 300ms 窗口 —— 要复现它得在真内核上拖动再切语言，jsdom 里做不到。
- 「切语言不丢内容」只验了文字，**没有**验像素：重建后的布局由内核重算，与重建前的位置不保证逐像素一致（§7.2 第 4 条管的是**文件字节**，不是视口）。

## 重审条件

- `mind-elixir` 下一次升级若改了 `LangPack` 的键集合，`lang-pack.ts` 会**编译期**报错（类型来自包）；那时核对新增的键有没有对应文案，而不是让它退回英文默认。
- 若将来内核支持「运行时更新语言包」，这个重建就可以撤掉，`locale` 从依赖数组里拿掉即可 —— 判据是那条 `innerHTML` 有没有被换掉，不是别的。
- 若选中项 / 专注模式 / 平移位置变成了公开 API，`scaleRef` 那一族可以一起扩成一份「重建时要还原的视图状态」。
- 若 `ui.mindmap.*` 里某一条被本项目别处复用（例如把「插入子主题」用在命令面板上），它就该回到 ADR 0031 的目录复用约定，而不是各自抄一份。
