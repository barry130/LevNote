# 0037 · 菜单栏：自绘 web 菜单，命令的另一个入口

日期：2026-10-05（内容充实：2026-10-06）
状态：已采纳
关联：0031（i18n 骨架）、ADR 0032（自定义快捷键）、0033（内核动作由内核实现的同一条理由）

## 背景

应用此前没有菜单栏：所有功能入口靠工具栏按钮、活动栏、命令面板与快捷键。
对比 Typora 这类桌面编辑器，用户缺少一条「按类别浏览功能」的路径 ——
命令面板要**先知道要找什么**才搜得到，菜单栏的价值恰恰是「不知道有什么
的时候可以逛」。

## 决策

### 1. 自绘 web 菜单，不用 Tauri 原生菜单

每个菜单项的可用性来自 `CommandRegistry.enabled`（保存判只读、检索判
有没有文件夹、源码模式判内核能力），那是**前端的实时状态**。原生菜单要
么做成静态的（点了禁用项），要么每次状态变化跨 Rust 桥整表重建；而命令
的标题、快捷键写法、i18n 也全在前端这一层。自绘之后这条链路一厘米不用跨。

代价是快捷助记（Alt+F 直开文件菜单）要自己实现 —— 刻意**不做**：菜单项
显示 `(F)` 助记（与 Typora 同形），但 Alt 组合键留待真实需求出现再加，
不为对称而加一个全局 Alt 拦截层。

### 2. 菜单只是命令的另一个入口

`ui/MenuBar.tsx` 的 `MENUS` 只是一份「哪个菜单放哪些命令 id」的数据；
显示什么（标题、快捷键）、能不能点（enabled），全部从 CommandRegistry
现查。菜单不带任何自己的语义 —— 与工具栏、活动栏、命令面板同一条约定：
**答案必须来自同一个地方**，否则迟早出现「菜单里能点、面板里是灰的」。

为此新增了 19 条命令把菜单填成真的：格式 4 条（加粗/斜体/删除线/行内代码，
`formatting.toggleInline` 的薄封装）、段落 12 条（标题/正文/引用/列表/代码块
走 `toggleBlock`，表格/数学块/图表/分隔线走 `insertBlock` —— 与斜杠菜单
同一入口）、主题 3 条（`setTheme` 的直接入口，`paper`/`ink`/`system`）、
关于 1 条（版本号经 `import.meta.env.QINGMO_VERSION`，硬约束 14 的写法）。
这些命令进了 BUILT_IN_COMMANDS 之后，命令面板与自定义快捷键**免费**获得
它们 —— 那正是「能力清单唯一」要的效果。

### 3. 键盘纪律沿浮层菜单的旧例

菜单开着时焦点多半还在编辑器里，监听挂 **window 捕获阶段**，处理完的键
`stopPropagation` 拦下（坑 9）：Esc 只收菜单，不连带触发全局 ui.escape；
上下键在启用的项之间移动焦点，左右键在顶层菜单之间切换（保持展开），
Tab 收起让焦点循环回正常顺序。收起状态**不挂**任何键盘监听 ——
编辑器正在打字时，一个常驻的 keydown 关卡纯属浪费。

### 4. 内容充实：每一项都接上真实能力（2026-10-06）

菜单内容参考 Typora（**不要求逐项一致**）：一条项要么对应一条已有命令，
要么为此新建命令 —— **没有对应能力的项不进菜单**，不画点了没反应的占位。
第二轮新增的命令与能力：

- **编辑组**：撤销 / 重做走新的可选契约 `EditorHandle.undo/redo`
  （Markdown 内核用 `@milkdown/kit/prose/history` 的命令本体，
  **必须**包 `withUserEditOnView` 打用户编辑标记 —— 菜单点击不产生
  `beforeinput`，漏标记就是「撤销了但文档不变脏，保存写回旧内容」；
  代码内核用 `@codemirror/commands`，CM 的上报走 `updateListener`，
  无需标记）。两者**刻意不设默认快捷键**：内核各自的 keymap 已占
  Mod+Z，外壳再注册全局 Mod+Z 会在同一按键上跑两遍撤销。
  「复制为 HTML」复用 `toHtml()`，拿不到 HTML 时退回复制原文并**说明**。
- **文件组**：「保存全部」是 `WorkspaceStore.saveAll()`（逐个 await 而非
  并发 —— 每次保存都可能弹冲突对话框）；「新建文件」实现为
  **选位置 → 落一个空文件 → 打开**，本产品没有「无标题缓冲区」，
  文档生命周期以磁盘路径为主键，硬造内存新文档等于给每条生命周期链路
  加一个「还没有路径」的状态；撞上同名文件时明确拒绝（硬约束 2）。
- **视图组**：自动换行 / 代码行号是 `UiActions` 的两个意图方法，改的是
  **设置层字段**（与设置页同一份真相）；全屏走平台桥
  `toggleFullscreen()`（桌面 = Tauri 窗口级 `setFullscreen`，浏览器 =
  Fullscreen API，两处都在 `core/platform/` 里，F11 键位放行于
  `isAllowedInEditable` 的功能键白名单）。
- **勾选列**：`isChecked` prop 是三态的 —— `true/false` 画 ✓ 或留空槽，
  `undefined` 不画勾选列。菜单**只画状态不产生语义**：侧栏 / 大纲 /
  换行 / 行号 / 三档视图 / 三档主题的真相来源是设置快照与活动面板的
  视图模式，状态栏、设置页与菜单 ✓ 读的是同一份字段。

顺带修了一个既有缺陷：代码内核 `setValue` 的注释声称整篇替换
「不进撤销栈」，但只打了 SILENT 注解、漏了 `addToHistory` 注解 ——
打开文件后第一下 Ctrl+Z 会把整篇文档清空。补上
`Transaction.addToHistory.of(false)`（与 Markdown 内核 `setMarkdown`
的行为对齐）。

**明确不进菜单的项**（都没有真实能力支撑，或属于另一条决策的范围）：
最近打开的文件列表（无会话内历史记录）、按指定编码重新打开（编码探测
是打开时一次性决策，见 format-spec §3）、插入链接/图片的菜单项（斜杠
菜单与工具栏已有入口）、缩放（无字号缩放实现）、打字机模式 / 专注模式
（未实现）、目录 / front matter 工具（未实现）、纯文本与导图内核的
撤销（契约没实现就禁用 —— 内核没给的能力菜单不假装有）。

## 后果

- 标题栏下方多一行菜单栏（约 28px 高）；chrome 区与下拉面板全部使用
  现有 token（`--chrome-*` / `--surface-*`），不新增颜色。
- 「格式 / 段落」命令只在 Markdown 文档上可用（`formatting` 契约只有
  Markdown 内核实现），其它内核上灰着 —— 与 view.toggleSource 同一条
  「禁用而不是隐藏」的呈现。
- 无默认快捷键给格式/段落命令（Ctrl+B 已被侧栏占用，不模仿 Typora 的
  键位去顶掉既有约定）；用户可以在设置里自己录。
- `undo/redo`、`copyHtml` 等 15 条新命令进了 BUILT_IN_COMMANDS 之后，
  命令面板与自定义快捷键免费获得它们；`EditorHandle.undo/redo` 作为
  可选契约，两个实现了的内核自动可用，未实现的（导图）按禁用显示。

## 重审条件

- 出现「全屏 / 自动隐藏标题栏」这类窗口形态需求、或需要系统级 Alt 助记
  时，重审原生菜单 —— 届时桥接方案以「整表推送 + 事件回执」为准。
- 若菜单项数量继续膨胀（单菜单超过 15 项），引入子菜单而不是继续拉长
  （「文件」组目前 12 项已接近）。
- 若用户给撤销/重做自定义全局快捷键导致双击撤销的反馈增多，评估在
  注册表层面识别「内核 keymap 已占用」的键位并提示。
- Typora 的「最近打开」「按编码重新打开」「缩放」「打字机模式」被明确
  拒绝在本次范围外 —— 若其中任何一项将来立项，那是新能力（会话历史、
  重新探测管线、字号偏好、编辑模式），走各自的 ADR，不在菜单里硬凑。
