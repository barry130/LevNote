# 0035 · 块级互操作第一步：结构变换（L3）与引用卡片

日期：2026-10-05
状态：已采纳（P6 第 28 项的第一阶段）
关联：0002（doc-block 格式）、0021（位置记忆的「内核定坐标系」原则）、format-spec §1–§5

## 背景

`docs/format-spec.md` 定义了四类文档互操作的三个层级：L1 引用、L2 就地编辑、
L3 结构变换。规范的可执行实现（`@levnote/interop-spec`，27 条测试）早已就位，
但应用本身只消费过它的一小半 —— `kind: diagram` 的引用块能画成图（ADR 0027），
其余 kind 的 doc-block 在编辑器里只是**一段普通围栏文本**：
用户看得见属性区，却没有任何与「引用」这个语义相关的体验。

第 28 项要的「完整体验」体量太大，无法一次做完。本 ADR 记录第一阶段交付什么、
**刻意不做什么**、以及为什么这一刀切在这里。

## 决策

### 1. 「提取为引用 / 拉平引用」两个命令（L3 全部）

- **提取为引用**（`edit.extractReference`）：把选中内容写成一个新 `.md` 文件
  （文档同目录），选区原地替换成指向它的 `doc-block` 引用。
- **拉平引用**（`edit.inlineReference`）：把光标所在的 doc-block 引用替换成
  它指向的内容 —— `mode: reference` 去读文件，`mode: inline` 展开载荷。

分工沿图片粘贴的旧例：**文档坐标的事归内核，文件系统的事归外壳**。

- 内核新增可选契约 `EditorHandle.blockTransform`（只有 Markdown 内核实现）：
  `selectedMarkdown` / `replaceSelectionWith` / `enclosingFence` /
  `replaceEnclosingFenceWith`。读写都走 **Markdown 源**而不是文档模型结构体 ——
  与 `roundTrip`（ADR 0033）同一条理由，翻译由内核自己做。
  两个写方法都经 `withUserEdit` 打 `USER_EDIT_META`（硬约束 7；
  实现本体从 `setup.ts` 拆进 `user-edit.ts`，避免写成两份）。
- 外壳的编排逻辑在 `core/document/block-ops.ts`，依赖（读文件 / 写文件 /
  通知）全部注入 —— 命令层是薄壳，编排被假依赖单测钉住。

### 2. 引用卡片（L1 的展示层）

`mode: reference` 且 kind 为 **markdown / mindmap / text** 的 doc-block，
在编辑器里画成一张卡片（标题、kind、`来自 <src>`），点击打开被引用的文档；
光标进块仍显示源码 —— 双态机制与图表块共用同一条容器与 CSS。

- **`kind: code` 的引用不画卡片**：那是「这段代码在这里」的原样呈现，
  藏进卡片后面没有意义（与 ADR 0027 里「不硬画成图」是同一条判断）。
- **`mode: inline` 不画卡片**：内容就在块里，没有「另一个文件」可打开。
- **不认识的 kind 不画卡片**：规范 §2.3 的「按 text 兜底」是格式层的约定；
  展示层不知道未知的 kind 会不会真是别的东西，把原文藏起来等于替用户做决定。
- 点击走 `EditorMountProps.onDocBlockOpen` 契约交出**解析好的属性** ——
  监听挂在内核自己造的元素上（硬约束 11），外壳不重复解析围栏文本。

### 3. `resolveRelative`（路径风格的边界修正）

卡片点击链路暴露了硬约束 12 的一个变体：`joinPath(dirname(docPath), src)` 里
`dirname` 会**丢掉分隔符信息** —— `notes\main.md` 的目录是裸名 `notes`，
`joinPath` 对没有分隔符的 base 只能按 `/` 拼，产出 `notes/detail.md`，
与磁盘上的 `notes\detail.md` 是两个字符串。新增 `core/path.ts` 的
`resolveRelative(docPath, src)`：以**完整文档路径**的风格为准对齐分隔符；
`store.resolveDocBlock` 一并切换（同一语义，同一处修）。

## 后果

- 四类文档的互操作从「图表能看」推进到「Markdown 文档可以拆分 / 合并、
  引用可以点开」；`@levnote/interop-spec` 首次被应用本体消费。
- 新文件**立即**写盘、宿主文档变脏等正常保存；命名绝不覆盖（撞名自动加序号）；
  拉平**不删除**被引用的文件 —— 每一步都在状态栏说明发生了什么（绝不静默）。
- 提取范围限定在**同目录**：跨目录相对路径要处理 `..` 折叠，
  `joinPath` 刻意不做这件事，本阶段不为它破例。

## 明确推迟（本阶段不做）

- **L2 就地编辑**（在主文档里直接编辑被引用的文档、保存回原文件）——
  需要嵌套内核或「面板叠加另一份 store」的架构决策，单独一个 ADR。
- 引用卡片的**内嵌预览**（卡片里直接渲染被引用文档的只读渲染）——
  与 L2 共享大部分架构，推迟到那时一起定。
- 图表 / 导图引用的拉平：内容塞进 Markdown 正文是降级不是转换，**明确拒绝**
  并说明原因（不是「暂不支持」，是「不该做」）。

## 重审条件

- 若用户大量提取后反悔（拉平），而「拉平不删文件」造成孤儿文件堆积，
  考虑在拉平时检测「引用此文件的所有块都已拉平」并**询问**是否删除。
- 若 L2 就地编辑落地后证明「卡片 + 打开标签」的形态不再需要，
  卡片可以降级为纯说明（去掉点击）—— 但格式层的 doc-block 语义不变。
- 若未来出现跨目录引用的真实需求（比如目录化的 notes 库），
  再评估是否给 `joinPath` 补 `..` 语义 —— 那是硬约束 12 注明的重审入口。
