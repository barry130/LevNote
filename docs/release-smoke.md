# 发布冒烟清单（release smoke）

> 发版前**人工**跑一遍的清单。单测（1,541 条前端 + 66 条 Rust）覆盖的是我们想到的路径，
> 而发版要兜住的是「自动化天生测不了」的那一批：真布局、真渲染、真文件系统、真对话框。
> 这份清单把那批事**点名**，每一条都写了**为什么只能人工测** —— 没写理由的条目不该出现在这里。
>
> 跑完把结果记进当次发布的 release notes（全过 / 哪条没过、为什么放行）。

---

## 发版次序（现状：门禁已自动、发版仍人工）

仓库已绑定到远端（`https://cnb.cool/canace/LevNote`，2026-10-09）。
**门禁已接通**：`.cnb.yml` 在每次 push / PR 上跑第 0 步那套（typecheck / lint /
test / build + cargo test / fmt / clippy）—— 但它只**验**不**发**。
`.github/workflows/ci.yml` 是 GitHub Actions 格式、CNB 不跑它，留着给 GitHub 侧用。

**发版流水线（出安装包 + 签名）仍未接通**：签名主体未到位（B3 / B4）——
所以发版的第 3–6 步现阶段仍是人工动作，**次序即依赖**：

1. 改版本号三处（`package.json` / `src-tauri/Cargo.toml` / `src-tauri/tauri.conf.json`），
   `CHANGELOG.md` 加对应小节；
2. 第 0 步自动门禁全绿；
3. `pnpm run desktop:build` 出安装包；
4. **拿安装包（不是 dev 跑出来的）**走完第 1–3 步冒烟 —— 测的就是用户拿到的那份字节；
5. `git tag v<版本号>` 并写一句 release note（冒烟结果记在这里）；
6. 安装包与 release note 归档到发布位置（现阶段人工保管）。

发版流水线（出包 + 签名）与签名主体到位后，第 3–6 步交给流水线
（产物上传 + 签名），本清单的第 4 步**不随之自动化** ——
挑一条真机人工冒烟永远保留。

## 第 0 步 · 自动门禁（先跑，全绿才轮到人工）

```bash
pnpm run check                                        # typecheck + lint + 1,489 条测试
cargo test --manifest-path src-tauri/Cargo.toml       # 66 条 Rust 测试
pnpm run licenses                                     # 升过依赖才需要：重算许可证清单
```

版本号三处一致（`grep` 一遍）：

- `package.json`
- `src-tauri/Cargo.toml`
- `src-tauri/tauri.conf.json`

（`packages/interop-spec` 是独立包，版本不随应用走。）

## 第 1 步 · 构建与安装

- [ ] `pnpm run desktop:build` 成功，产物在 `src-tauri/target/release/bundle/`
- [ ] 安装包能装、能启动；「关于」里的版本号与发布号一致（版本号经 `define` 注入，
      **开发时崩、打包时好**或反过来都有先例 —— 硬约束 14）
- [ ] 装完后的应用**断网能启动、能打开文档**（ADR 0001：纯本地是产品承诺，不是实现细节）

## 第 2 步 · 核心链路（四类一等公民各走一遍）

- [ ] Markdown：打开示例文档（帮助菜单 → 示例文档）→ 改一个字 → Ctrl+S → 重开内容还在
- [ ] **新文档第一个字**：新建空文件 → 敲一个字 → Ctrl+S → 磁盘上有那个字
      （坑 11 的最短暴露路径：只错第一次，自动化几乎抓不到）
- [ ] 代码文本：打开 `.ts` / 无扩展名文件，行号 / 高亮 / 查找替换正常
- [ ] 思维导图：打开 `.mindmap`，增删节点、保存、重开
- [ ] draw.io 引用：Markdown 里 `kind: diagram` 的块渲染出图，全屏查看可用
- [ ] 保存不改写没碰过的内容：打开一份用 `-` 写的文档 → 改一个字 → 保存 → `git diff` 只有那一行
      （往返保真最便宜的判据；`diagnostics.roundTrip` 命令可辅助）

## 第 3 步 · 人工实测项

### 3a. 滚动与布局 —— jsdom 没有布局引擎，单测里一切滚动都是假象

- [ ] 位置记忆：滚动到文档中部 → 关闭 → 重开，光标与滚动都回来
- [ ] **切视图保留滚动**：富文本滚到中部 → Ctrl+/ 切源码，滚动比例跟过去；切回来同理
      （两边的 `textLength` 坐标系不同，恢复的是**比例**不是光标 —— 这是设计好的分支，
      但「比例在真窗口里对不对」只有眼睛能判）
- [ ] 长文档能滚到底（硬约束 13 的回归：CSS 所有权错了的表现就是「滚不动」）
- [ ] 分屏：滚左栏，右栏跟着走；比例别飘
- [ ] **打字机模式**：设置页或视图菜单打开 → 光标行立刻在正中，逐行下移都跟着；
      关掉后再打字页面不再自己滚（ADR 0039 §4 —— 单测里这条是空操作）
- [ ] **专注模式**：Markdown 里光标所在块亮、其余调淡，移到别处亮块跟着走；
      导图 / 纯文本里点开是「什么都没发生」，属预期（设置页提示里写了范围）

### 3b. 渲染 —— 单测里全是假渲染器，真图只在真 WebView 里出现过

- [ ] Mermaid 图画出来、全屏查看清晰（画错/重叠只有人工能看见，坑 16）
- [ ] KaTeX 公式（行内 + 块级）排版正常
- [ ] draw.io 查看器：引用的图渲染，缺 stencil 时**界面有提示**而不是静默缺形状（ADR 0005 文末）
- [ ] 代码高亮：切几种语言看一眼（高亮每次文档变更整篇重跑，顺手确认长代码块打字不卡）

### 3c. C1 · 打印 / 导出 PDF（打印链路全在真窗口，jsdom 零覆盖）

打印与 HTML 导出**共用同一份渲染**（`buildSelfContainedHtml`），所以两者一起测：

- [ ] **大文档打印**：打开几百段的 Markdown（`docs/format-spec.md` 即可）→ 菜单「打印」
- [ ] 打印**子窗口**能打开：内容出现、不是白屏；应用整体**没被卡死**、能正常关掉
      （`print_html` 曾因做成同步命令死锁 —— 表现就是白屏 + 全应用关不掉，ADR 0030 §6；
      这个缺陷的形态只有真机看得见）
- [ ] 系统打印对话框里选「另存为 PDF」，产物：中文不缺字、表格/代码块/图片/公式/Mermaid 都在、页数合理
- [ ] 打开几百 KB 且带图的文档打印，不崩（图片走 `read_binary_file` 内联，量大时才暴露）
- [ ] 导出自包含 HTML：断网双击打开 —— 图、公式、样式全部就位（单测只验 CSS 被内联了，
      「浏览器里真长得对」必须人工看）

### 3d. Tauri / 操作系统面 —— 浏览器与 mock 都没有这些东西

- [ ] 原生对话框：打开文件夹、保存、删除确认
- [ ] **窗口标题（真机）**：打开 `a.md` → 标题栏显示 `a.md — 轻笺` → 设置页切 English
      → **那一刻**标题栏变成 `a.md — LevNote`。浏览器面只见 `document.title`，
      桌面下真实通道是 Tauri 的 `set_title`（单测只能钉「有没有再调一次、
      带的是不是新文案」，**真窗口上到底刷没刷**只有真机看得见）。
- [ ] 文件监听：应用开着时用记事本改同一个文件 → 出现外部改动提示；选「从磁盘重新加载」内容正确
      （notify 的事件在真文件系统上才发生；mtime 判决、防抖窗口都是真机行为）
- [ ] 图片粘贴：截图 → Markdown 里 Ctrl+V → 落盘到 `<文档名>.assets/`、相对路径、显示成功
- [ ] **链接激活**（ADR 0040，新增 Rust 依赖 `tauri-plugin-opener`，单测里 `openExternal`
      是非桌面必 reject，真路径一次都没跑过）：富文本视图里
      ① Ctrl+click 另一个 `.md` → 在本工作区开成新标签页；
      ② Ctrl+click `[跳过去](#第二节)` → 光标落到那一节、**窗口没有导航走**；
      ③ Ctrl+click 一个 `.png` 的相对地址 → **系统的图片程序**打开它；
      ④ Ctrl+click `https://…` → 系统浏览器打开；
      ⑤ 四种失败（锚点不存在 / `[占位](#)` / `javascript:` / 裸文件名文档里的相对地址）
      各给一句话，且**编辑器的光标与未保存改动都还在**。
      最要紧的是 ②③ 之外的那一句：**任何一次点击之后，轻笺窗口还停在原文档上** ——
      「导航走」这条在 jsdom 里根本无法发生（没有 webview），只有真机能验。
- [ ] **拖入多个文件**（ADR 0041，单测走的是 `emit('tauri://drag-drop')` 伪事件，
      真 OS 拖放只有真机发生）：一次把 3 个文件拖进窗口 → **三个都开成标签页**；
      其中混一个打不开的（不存在 / 只读）→ 另外两个照开，且**弹一句话点出没打开
      的那个文件名**；三个全坏 → 说「都没能打开」并列出三个名字；三个全好 →
      **一句话都不说**（成功安静是刻意取舍）。
- [ ] **全屏（ADR 0041，唯一百分之百假的一条）**：主窗口菜单或 `F11` 切全屏 →
      真的全屏 → 再切回来。**jsdom 里 `requestFullscreen` 是 undefined，
      单测那条「命令失败有一句话」正是靠它必失败才写得出来的** ——
      也就是说「全屏能不能开」一次都没被执行成功过。
- [ ] 编码：GBK 文件打开不乱码 → 改 → 保存 → 用别的工具验不乱码；UTF-8 BOM 保存后保留
      （编码探测与 BOM 策略的测试用的是字节流，「用户看到的不是乱码」要眼睛确认）
- [ ] 中文输入法：富文本里连续上屏、候选窗不丢字（坑 11 的 `beforeinput` 链路，输入法才踩得全）

### 3e. 键盘与浮层 —— 捕获阶段、焦点、命中区，全是真实焦点环境的行为

- [ ] 浮层工具条：选中文字浮出 → 点加粗生效；斜杠菜单 `/` → 键盘上下回车选择，
      **不多出空行**（坑 9：键盘要抢在 ProseMirror 前面）
- [ ] 菜单栏：Alt/点击打开 → Esc 收起 → 编辑器焦点还在、能继续打字
- [ ] 命令面板（Ctrl+Shift+P）：搜、选、执行；快捷键表与实际一致
- [ ] 块手柄：悬停出手柄 → 上移/删除/拖动落点正确（几何在真窗口才有意义）

### 3f. 工作区级新功能（有单测，但真盘组合行为再走一遍）

- [ ] 文件树右键区：新建 / 重命名 / 删除；重命名后**已打开的标签页**跟着改名、
      未保存的改动**还在**；删除时打开着的脏文件被**拒绝**并说明原因
- [ ] 跨文件替换：小工作区（含一个 GBK 文件）替换一轮 → 未打开的文件被替换且编码不变，
      打开且脏的文件被跳过并在结果里列出来
- [ ] 最近文件：文件菜单里出现刚关的文档，点击能打开；清理后列表为空
- [ ] 语言切换（**分主语**，各区域归属不同代码域，别串在一起断言）：
      - **外壳画的部分**（`src/ui/**` + 命令面）：设置页切 English →
        菜单顶层名与**下拉项**、命令面板 placeholder 与**条目**、
        快捷键表**分组名与条目**、设置页 / 文件树 / 大纲 / 检索面板 /
        标签栏 / 状态栏全部变英文。四项一起看 —— 命令面（下拉项 /
        面板条目 / 快捷键表）是 `core/commands/definitions.ts` 的惰性
        文案，2026-10-09 前它们**只变顶层名、不变条目**，是一条真实缺陷
        （#TASK-I18N-CMD-LIVE-01，已修）；只盯菜单顶层名会漏掉它。
      - **快照型文案要「先让它上屏，再切语言」**（#TASK-I18N-SNAPSHOT-01）
        —— 这两处不看「切完再做一次动作」，那是查不出问题的：
        - **窗口标题**：打开 `a.md`（标题显示 `a.md — 轻笺`）→ 切 English
          → 标题栏**那一刻**就变成 `a.md — LevNote`，不必切标签或做别的动作。
          修之前它停在中文（effect 的 deps 漏了 locale）。
        - **状态栏那句话**：打开文件后状态栏右侧出现「已打开 a.md」
          （`文档还需保存` / `已替换 N 处` 同理）→ 切 English →
          **同一句**当场变成 `Opened a.md`。
        - **错误横幅 / 冲突横幅**：只读文件点保存（横幅出现）→ 切 English
          → **同一句**当场变英文；冲突横幅同理（外部改动 + 本地也有改动）。
        - 查找栏的「已替换 N 处」也在这一批里（同一个快照族）。
      - **编辑器里由内核画的浮动说明与按钮仍是中文**（代码块语言标签与
        「正在渲染图表…」、公式「正在渲染公式…」、图片「无法显示本地
        图片：…」、导图与引用卡片上的按钮）—— 内核（`src/modules/**`）
        零 i18n 接入，**已知部分覆盖，记进 release notes，不当 bug 报**。
      - **已知残留**（不是「唯一一处」，均不当 bug 报、各在
        #TASK-I18N-SNAPSHOT-01 的 ADR 0031 复评记录四里登记）：
        粘贴图片失败时状态栏那句话（`core/document/images.ts`）；
        跨文件替换汇总（`core/search/replace.ts` → `SearchPanel.tsx` 存 state）；
        文件树报错文案（`core/workspace/store.ts` 的 `tree.error` 一族：
        `failTreeAction` 的 10 处调用 + `core/path.ts` 的 `validateEntryName()`）；
        引用卡片摘要（`core/document/block-preview.ts`）交给内核的两个译文字段
        —— 读不到时的原因，与 `>40` 行 text 引用里那行截断尾「……（共 N 行）」
        （`core.bprev.truncatedN`，内核不重问语言就不重算）；同一契约字段在 `App.tsx` 的
        `resolveDocBlockPreview` 里还有一处（**白名单内**但同因登记）——
        修它要动 `core/editor/types.ts` 的契约（白名单外），且**该分支生产
        不可达**：标签页只在 `store.open()` 成功后入列、`doc` 恒非 null，
        唯一能把 `doc` 置 null 的 `close()` 在生产代码里无人调用；
        代码块语言面板搜索框里「使用 “xxx”」那一行（`ui/CodeBlockPicker.tsx`
        的 `useMemo` 把 `t('ui.codeblock.useTyped')` 塞进**被渲染的**行对象）；
        公式 / 图表渲染失败时内核画的那句话（`core/katex.ts` /
        `core/mermaid-render.ts` / `core/drawio-render.ts` 的 `Render.message`）；
        设置页的按键安全提示（`SettingsDialog.tsx` 的 state）。
        另有一处**表面相同、根因不同**：保存冲突横幅（`save()` 的冲突分支）那句
        来自 Rust（`src-tauri/src/fs/mod.rs` 的硬编码中文）—— 是这一侧
        没有 i18n 通道，与内核零接入同源，不属快照族。
        上列**多数在白名单外**，只有 `App.tsx` 那一条是白名单内（理由已随行写明），
        均另立 follow-up。
        > `DocumentPane.tsx` 的 `editorError` **不在**此列 —— 它存的是内核
        > 抛出的原始错误，不是查好表的译文，本就不属这一族。

## 平台备注

- 本清单在 **Windows** 上制定与实测；列出的条目全部按 Windows 路径写。

## 放行标准

第 0–2 步有任何一条不过 → **不放行**。
第 3 步某条不过时，先归因：是缺陷（放行前修或回退）还是已知限制（写进 release notes，
并与 `docs/open-decisions.md` 里对应的条目对上号）。**「没测」不是放行理由，记录下来才是。**
